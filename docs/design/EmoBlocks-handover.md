## 1. 先理解项目

EmoBlocks 只有一条主线：**从给定主题发展音乐素材，再按情绪线编配、衔接为连续作品。** 内容发展、情绪演绎和连接是三个协作层，不是三个产品方向。

当前是可运行的本地规则 Demo，不是已接入生成式 AI 的完整产品。规则负责自动选择和执行音乐手法，用户不必逐轨编配。默认确定参考主题、允许有限发展，不要求所有阶段逐音符锁定；当前连续编配路径保留所选旋律音高与节奏。

阅读顺序：[Idea](EmoBlocks-idea-overview.md) → [步骤与当前进度](EmoBlocks-implementation-goals.md) → 本文。早期[开发与验证计划](EmoBlocks-development-plan.md)用于查参考项目，其排期、默认锁定与 Web 架构不是当前实施要求；[历史决策](EmoBlocks-decision-history.md)不作为待办执行。

## 2. 已交付与尚未完成

| 部分 | 当前可用能力 | 仍有边界 |
|---|---|---|
| 步骤1：情绪编配 | 六情绪、和弦伴奏、配器、密度、力度、有限回应／句尾变化 | 合成音色，情绪辨识与听感待验收，无生成式 AI |
| 步骤2：内容发展 | 原主题、同源变体、单参考回答句、中性试听、候选保存与来源追溯 | 非任意续写，无多参考融合和完整对比段生成 |
| 步骤3：连续作品 | 固定骨架、同源替换、许可位置插入、跨块情绪区间、边界处理、整段渲染 | 编辑后重新规划整段；无局部编配保持和独立过渡块 |
| 当前界面 | 单窗口快速／精细模式、多旋律输入、结果历史、播放块高亮、保存导出 | 无播放拖动跳转；曲线是块级标签与线性强度，不是自由多维曲线 |
| 分享包 | Windows 程序、运行组件、源码、输入与试听样品 | 已做本机启动自检；其他电脑兼容性尚未验收 |

六情绪：平静／安定、温暖／希望、悲伤／失落、悬疑／不安、紧张／危机、振奋／坚定。“高潮”是强度与发展位置，不是第七种情绪。

输入范围：MIDI type 0/1 或未压缩 MMP，用户指定旋律轨／选区；固定 4/4、40～220 BPM、每块 4～8 小节，同池统一 BPM 与调性参考。快速模式最多六块，连续作品上限 128 小节。多声部须明确选择保留高／低音等整理策略，不宣称自动找到了主旋律。

未完成：WAV 旋律提取、自由变速转调、镜头精确时长适配、生成模型、歌声合成、专业分轨交付、跨 DAW 验收及游戏实时调度。

## 3. 如何运行和演示

### 分享包

文件：`EmoBlocks-Windows-with-Samples-20260917.zip`，约 82.5 MB。先完整解压到可写目录，再运行根目录 `EmoBlocks.exe`。不需要另装 Python，不要只复制 exe；程序需要同目录的 `_internal`、`app` 和 `runtime`。

压缩包内 `samples` 有原始平静版 MMP、三份 MIDI 输入、原主题／变体／回答句试听，以及 `Emotional-Flow-65s.wav` 和对应 MIDI。说明见根目录 `README.txt`。本文档包另行提供，不会静默替换先前的程序压缩包。

### 两条演示路径

1. **单旋律快速成品**：导入一段旋律 → 选择段数与情绪线 → 自动发展回答句并生成 → 播放、查看当前块 → 导出。
2. **多主题与精修**：逐段加入输入列表 → 确认 A/B/C 顺序 → 设置情绪 → 生成 → 切换精细模式调整素材、结构和连接。

多主题快速输入会全部保序使用，不自动补回答句；需要更多内容发展时到精细模式操作。使用平静版 MMP 时，遇到同时起音须明确选择整理方式，不能默默删音。

快速模式的情绪线是下一次创作模板；精细模式修改当前作品。修改参数不会改变旧音频，需重新生成。自动选中候选不等于用户已认可听感。

## 4. 开发入口与数据流

仓库文件位于 `outputs/`；分享包对应源码位于 `app/`。以下路径相对于这两个根目录：

| 文件 | 职责 |
|---|---|
| `EmoBlocks/app.py`、`unified_ui.py` | 主入口、单窗口界面、后台任务与交互 |
| `EmoBlocks/studio_model.py` | 快速／多主题编排、工程保存恢复及播放时间表 |
| `EmoBlocks/structure_engine.py` | 固定骨架、来源关系、变体替换与插入授权 |
| `EmoBlocks/flow_engine.py` | 跨块情绪、全曲和声配器、边界处理及连续渲染 |
| `EmoBlocks/audio_player.py` | Windows MCI 播放及实际设备位置 |
| `EmoBlocks-Step2/material_engine.py` | 素材池、内容变体、关联回答句与中性试听 |
| `EmoBlocks-Step1/engine.py` | MIDI／MMP 解析、规则编配、MIDI／MMP 输出和 LMMS 调用 |

调用方向：界面 → 工作台状态 → 结构／整曲引擎 → 素材引擎 → 步骤一基础音乐工具。步骤一、二独立程序保留，但主程序不再打开它们。

实际技术栈：Python 3.9、Tkinter、Mido、NumPy、LMMS；Windows 播放用 MCI，分享包用 PyInstaller。规则阶段不需要 GPU 或租服务器。源码启动器含开发机路径，换电脑优先用分享包；开发环境需自行配置 Python 与 LMMS。引擎优先查找包内 `runtime/LMMS/lmms.exe`，否则回退开发机路径。

素材池保存音符、来源、参数、种子与版本；结构保存骨架及使用实例；工作台保存素材、结构、曲线、输入列表与结果索引。结果位于 `EmoBlocks/renders`，工程快照位于 `EmoBlocks/projects`。结果音频仍通过路径引用，跨机器搬工程时需要带上音频或重新生成，不是自包含工程归档。

## 5. 接手时不能破坏的约束

- 已确认 A→B→C→D 不得自动改成 A→C→D→B；变体只能替换同来源主题。回答句默认在来源主题之后，其他位置须明确授权。
- 内容块与情绪区间是不同概念；同一情绪可覆盖多个块。当前区间边界对齐块，块内情绪类别变化是后续目标。
- 关联素材 E 可独立复用；过渡块依赖指定两端，不能以 E 冒充已实现的独立过门。
- 同一时间线上统一编配、一次渲染；不把独立试听 WAV 的尾音逐段拼入。作品末尾另计一秒尾音。
- 输入、已保存素材与旧结果不覆盖；失败操作不损坏当前工程。不要将“未修改旋律”宣传成“未修改整块伴奏”。
- 播放块定位必须读取所选结果的时间表，不能使用当前编辑结构去解释旧音频。
- 继续保持一个创作主窗口，进度与错误内联显示；标准文件选择对话框可保留。

“非静音／无削波／测试通过”不等于自然、好听或情绪正确。现有关闭连接的版本仍共享全曲规划，不是“独立块直接拼接”基线。

## 7. 建议下一轮工作

1. **先做听感验收**：用不同主题对照六情绪、原主题／变体／回答句和连接开关；记录接受／拒绝原因，优先修正重复、和声冲突与突兀边界。
2. **实现真正局部修改**：定义块、边界、尾音依赖；冻结未影响的音乐事件，保存参数与种子，复用候选和编配。验收：改中间块后非影响范围事件保持一致，并展示实际差异；可先全曲重渲染，不能借此重新作曲所有块。
3. **再扩展音乐能力**：有明确时长的独立过渡块、块内情绪变化，再评估更好音源或一个生成模型，不同时迁移平台和接入多个模型。
4. **完善交付**：另一台 Windows 实机验证、去除开发机路径依赖、工程相对路径／资源归档；公开分发前复核所有第三方二进制、素材、许可证及必要源代码交付。

可参考 AccoMontage2 的结构／伴奏思路、REMAST 的情绪过渡方法；研究实现均未在本项目部署。不能把接入模型或“情绪线生成音乐”本身当作首创。创新候选是主题来源管理、跨块情绪与受约束局部修改／连接修复的联合工作流，仍需对照结果支持。

需要项目发起人参与的部分：确认主题及允许变化范围、试听取舍、提供目标剧情／场景、确定参赛叙述与素材授权；不应要求其代替程序手工完成和弦、配器或变奏。
