# 强度画布 v2 团队与交接协议

产品基准：[curve-workflow-v2.md](curve-workflow-v2.md)。契约：[curve-workflow-contracts.md](curve-workflow-contracts.md)（DRAFT）。本轮只BOOTSTRAP；其余agent启动后等待用户粘贴角色prompt，不自动领功能任务。lead收到用户启动指令前也不实现产品功能。

## 角色与文件边界

| 逻辑角色 | 工作边界 | 禁止越界 |
| --- | --- | --- |
| lead-backend | 集成目录；需求/契约、v2时间轴与保存/撤销后端、任务分配、主流程路由及本地提交集成 | 唯一协调者；不推送/发布，不代答审批 |
| verifier | 对应集成目录，只读独立审查；在隔离输出目录运行必要验证 | 不修改源码/测试/文档，不提交，不把idle/done当PASS |
| music-algorithm | 算法独立worktree；预处理A/B/C/D、情绪轻改/记忆保护、连接、补全/推荐及授权范围内测试 | 不修改story_engine.py主流程或前端，不向其他角色派单 |
| frontend | 前端独立worktree；shared三栏/画布/共用播放器、配对适配器及授权UI测试 | 不修改后端算法/公共schema，不复制两平台UI，不向其他角色派单 |

以上为角色职责，不是本次功能任务授权。后续每个任务必须给出具体允许文件清单；候选新模块由lead先定义契约和所有权。`backend/core/story_engine.py` 主流程接线始终由lead负责，避免并发编辑。公共文档/接口调整也由lead协调，不能自行跨角色抢改。

## 分支、目录与运行记录

集成分支保存此前已完成但未提交的开发基线及三份共享文档。算法/前端从同一 `BASE_SHA` 创建独立Git worktree，仅提交各自工作分支；lead通过明确提交集成并解决冲突。不自动推送远程，不覆盖原分支或清理其他工作。

`BASE_SHA`、RUN_ID、实际agent名称/pane ID、目录/分支、焦点快照、基线文件清单及验收输出保存在仓库外本地运行目录，以lead交付的manifest为准。动态映射不写回Git，不因日志变化改变代码指纹。名称冲突使用本任务唯一后缀；只按真实名称或pane ID寻址，不按codex类型猜目标。

三个任务工作目录复用已有Python依赖环境。算法/前端的`.venv`是被忽略的本地环境链接，必须验证源码导入来自各自worktree。运行目录为每个角色提供 `run-python` 包装器，设置隔离数据、临时目录、测试输出和pycache；lead/verifier复用现有agent时也使用对应包装器，不能以启动前进程环境已被更新为假设。不重复安装、不将环境/用户工程/音频/LMMS提交。

## 阶段和依赖

| 阶段 | 交付范围与依赖 |
| --- | --- |
| P0 | 契约定稿与基线；BOOTSTRAP只给出DRAFT和基础布局 |

| P2 | 三栏素材操作、二维画布拖放和共用播放器；依赖P0/P1 |

每阶段实现→集成→冻结→verifier检查→修复→复验，最多5轮；第5轮仍未通过交付剩余问题，不声称完成。

## 任务信封

每项任务由lead发出，必须包含：

```text
RUN_ID:
TASK_ID:
ROUND:
WORKTREE:
BASE_SHA:
BRANCH:
ALLOW_FILES: 明确可修改文件列表，新增文件须说明
CONTRACT: 文档版本、输入输出、时间单位、错误/快照规则
ACCEPTANCE: 行为验收和需执行的命令
DEPENDENCIES: 已完成的任务/提交，未就绪时不越过
```

算法/前端交付：对应本地提交SHA、实际基准SHA、改动文件、实现摘要、测试证据与未验证项，结果留在pane供lead读取。其他角色不互相派单，不自动向lead回发唤醒消息。lead是唯一协调者，通过读取pane结果收集交付。

公共接口变更提交前，先更新契约并通知所有受影响角色；不自行兼容猜测中的字段。DRAFT不得被多个角色各自实现成不同接口。

## 冻结、独立检查和阻塞

lead集成后暂停所有受检代码写入，计算包含tracked、非忽略untracked源码/测试的指纹，提交RUN_ID、TASK_ID、ROUND、BASE_SHA、受检文件范围和fingerprint。verifier只读审查、运行必要验证，明确返回同一身份和受检指纹的PASS/FAIL/BLOCKED；FAIL列具体位置、条件、影响与缺失验证。

修复后重新冻结并计算指纹。只接受本轮且代码未改变的明确结论；Herdr idle/done只是可接收输入。超时/stalled先读实际状态和输出，确认提交，不盲目重发。blocked先读取原因并报告，不代替用户回答权限/授权界面。

## 验证与交付诚实边界

每次前端改动执行 `scripts/check_frontends.py`、`scripts/test.py`，另执行 `git diff --check`。使用隔离目录做故障/保存/渲染测试，不破坏用户工程和历史成品。

区分自动测试、程序化Tk、真实LMMS、真实设备流、人工视觉/听感和Windows实机。双主题、1020×700及常见更大窗口、缩放、焦点/滚轮/播放器契约须有对应证据；未进行的Windows125%/150%实机或人工听感不得标为通过。黑暗主题是静态Vibrancy风格，不是原生毛玻璃；情绪数据色为已授权例外。

BOOTSTRAP交付必须列：`BOOTSTRAP_READY`、RUN_ID、BASE_SHA、三个文档位置、四角色实际名称/pane/目录/分支、基线验证及未验证项。随后停止，等待用户启动指令。
