# EmoBlocks 音乐积木

> 2026-09-22 当前设计与实现：从一段灵感或多段旋律自动发展内容素材，再按“情绪种类 + 程度曲线”和固定记忆点编排音乐。约 2–4 秒短块保留主题/乐句来源与顺序，明确目标允许中断；连接先预留时间，留白充足可生成多块 Bridge。用户只需给出不完整的表达要求，系统填充其余部分。首版简要工作流已在本地规则实现，保留旧模式；非生成式 AI，不以质量评价为前置。详见 [当前实现计划](EmoBlocks-simple-workflow-plan.md)。下方 9 月 17 日的状态描述为历史记录。

> 更新：2026-09-17。步骤1～3的受限规则 Demo 已形成闭环：六情绪编配、素材变体／回答句、保序结构、情绪区间、边界连接、连续音频，以及单窗口双模式、多旋律输入和播放块定位。听感仍待验收；生成式 AI、独立过渡块、真正局部重编等仍属规划。进度以[实现目标计划](EmoBlocks-implementation-goals.md)为准。

## 1. 核心方向

**EmoBlocks 是一个以音乐积木为基本单元、由情绪曲线驱动的 AI 音乐创作系统，让音乐随着创作者设计的情感变化而发展。**

重点解决：**如何从创作者给定的主题素材出发，自动发展出相关乐句，按情绪线统一编配成完整作品；当局部情绪或场景时长改变时，保留已确认内容，只调整必要的音乐与衔接。**

系统区分三个协作层：音乐块承载音乐内容，情绪区间／曲线描述沿时间展开的表达，连接描述前后内容的衔接。一个情绪区间可以覆盖多个音乐块，一个较长音乐块也可以经历情绪变化，二者不要求一一对应。这是同一个创作系统的不同层，不是三个产品方向。

用户先提供参考主题，由系统发展主题变体与关联新乐句，形成可用素材池；随后用户选择或绘制情绪走向，必要时指定结构与时长。系统再根据情绪线自动选择素材、编排、配器、演绎与衔接。用户可以调整积木和连接，但不必逐轨编配或手工执行音乐处理手法。规则负责可执行范围与检查，AI／音乐生成模型作为规划和候选生成的可替换能力逐步接入。

默认是确定参考旋律并保持可辨认的主题特征，而非逐音符严格锁定。内容变奏和关联新素材均可按用户允许的程度生成；精确锁定特定音符或音频区域是可选约束，保留已确认块则是版本与修改范围的要求。

核心创作流程：

```text
提供主题素材 A、B、C、D
    ↓
统一规划内容发展：复用原主题、生成变体、按需生成关联新素材 E、F、G
    ↓
形成可用素材池，再设计情绪区间／情绪线
    ↓
按情绪区间选择和编排多个音乐块，自动配器与演绎
    ↓
处理连接关系，必要时生成独立过渡块
    ↓
连续试听、局部调整、保留已确认版本
    ↓
输出整首情绪流音乐及可编辑内容
```

## 2. Idea 简介

> **EmoBlocks 音乐积木，让人从几个主题出发，通过设计情绪来创作和修改整首音乐。** 创作者先给定主题素材，系统自动发展主题变体与相容的新乐句；形成素材池后，创作者再设计情绪线，系统据此编排音乐块、统一演绎并生成必要衔接。当局部表达或时长改变时，只调整受影响的内容与连接，保留其他已确认版本，交付连贯、可编辑的作品。

一句话介绍：

> **把音乐拆成积木，把情绪画成一条路。**

## 3. 产品亮点

### 3.1 可编排、可演绎的音乐积木

音乐积木首先来自创作者给定的主题、乐句、和弦与节奏；长旋律可以由用户指定或经系统建议拆为多个内容块。已有歌曲的主歌、副歌、Bridge 等片段是后续素材入口，不另立产品主线。音乐块不绑定唯一情绪，系统记录其主题归属、来源、音乐特征、叙事用途与可修改范围。

核心设计是明确“参考主题、内容变体、情绪演绎和已确认版本”的关系。允许在保持主题辨识度的前提下变奏；用户需要精确保留时，再分别指定 MIDI 音高、节奏、力度等约束。音频区域精确锁定意味着直接保留素材，不能宣称生成模型必然逐音符保持原样。

### 3.2 围绕同一情绪结构持续创作

系统可以根据情绪线自动选择原主题、内容变体或关联新素材。连续多个不同音乐块可归入同一个情绪区间，统一规划配器、和声方向与力度发展，而非各自生成后再拼接。用户仍可拖动块、替换候选、指定局部约束或修改连接，从自动草稿逐步精修。

### 3.3 情绪驱动，而不只是 BPM 驱动

系统不仅考虑 BPM 和调性，还综合分析：

- 能量与张力；
- 情绪倾向；
- 歌词与场景；
- 人声密度；
- 段落功能；
- 旋律辨识度；
- 相邻片段的兼容程度。

### 3.4 转场是一种情绪语言

连接有两种形态：一是作用于相邻块边界的连接关系，如配器交接、伴奏加密、延音衔接与和声解决；二是具有自身音乐内容和长度的过渡块，如过门、回答句或短桥段。系统根据前后两端的实际内容与情绪判断是否需要过渡，用户可以指定或覆盖选择。

不是每次换块都要加过门，也不是每次换情绪都要切块。过渡块需明确新增时长还是占用已有时间；音频素材可辅助使用 Crossfade、EQ、Echo 等处理，但不能将音乐连接简化为混音效果。

### 3.5 可解释、可局部修改

系统能够展示为什么复用某个主题、生成新乐句或采用某种连接。用户可以确认满意版本，只重新生成指定块、情绪区间或连接，无需推翻整段作品。改一个情绪区间可能影响其中多个音乐块，并非永远只改一个块。

系统需要根据依赖关系计算修改范围，包括目标块、相邻过门和效果器尾音。若总时长或节拍约束导致必须调整其他位置，应先展示冲突和受影响范围。未修改的块保留相同素材与相对内容；后续时间位置是否移动，由用户选择固定总时长或顺延时间线。

### 3.6 兼容专业音乐工作流

EmoBlocks 不取代 DAW 或音乐编辑器，而是作为它们上游的情绪编排工具和中间创作层。规划支持制作人导入 MIDI、音频 Stem、和弦与节奏素材，将结构、变奏和关联新素材以 MIDI、分轨音频、Tempo Map 和标记交付其他制作环境。当前仅实测本机 LMMS 工程与音频输出；Ableton Live、Logic Pro、FL Studio 等跨 DAW 兼容需另行验收，不宣称已经完成。

### 3.7 降低互动配乐的制作与修改成本

专业互动音乐已支持分段、分层和专用过门。EmoBlocks 关注制作这些版本和规则的成本：由创作者提供主题与约束，系统辅助生成所需变奏，并在情绪或时长变更后维护连接。游戏运行时优先播放预渲染积木；实时调度与实时生成分阶段实现。[Wwise 官方说明](https://www.audiokinetic.com/en/public-library/2024.1.8_8893/?id=creating_interactive_music&source=Help)

## 4. 原创素材工作流：从旋律积木到情绪流音乐

### 4.1 创作者提供什么

音乐制作人不必先完成整首作品，可以只提供最核心的音乐 DNA：

当前支持单段或多段 MIDI／受限 MMP 旋律输入，每块 4～8 小节；下列清单是后续可扩展素材类型，不代表均已支持。

- 一条或几条主旋律；
- 和弦进行；
- 鼓点或节奏型；
- Bass Line；
- 人声哼唱或歌词动机；
- 主题音色；
- 8～16 小节的短音乐块；
- 不同情绪阶段的参考段落。

每个原创积木可以设置用途和约束，例如：

```text
名称：主角主题
角色：核心旋律
允许变奏：节奏、配器、调式、力度
禁止修改：前四个核心音符
情绪范围：希望 → 紧张 → 坚定
可循环：是
```

以上“禁止修改”是用户主动选择的约束示例，不是所有素材必须设置的默认值。

### 4.2 内容发展：原主题、主题变体与关联新素材

给定 A、B、C、D 后，先进行内容发展，形成包含以下三类内容的素材池；这一环节不要求用户先设计情绪线：

| 类型 | 表示 | 含义 |
|---|---|---|
| 原主题素材 | A、B、C、D | 用户提供或确认的乐句／主题片段，可以重复使用 |
| 主题内容变体 | A_c1、D_c1 | 改写原主题的节奏、句尾、音程或动机，仍明显属于该主题的发展 |
| 关联新素材 | E、F、G | 参考一个或多个原素材的音乐语言，生成可独立使用的回答句、发展句或对比句，不只是移调或换音色 |

“合乎原旋律”需要同时考虑调性／和声语境、节奏动机、音程特点、乐句结构与主题辨识度，不是只落在同一音阶内。原素材之间存在冲突时，应选择相容的参考子集或提示用户，不将所有素材强行混合。

关联新素材可独立参与作品编排；过渡块则针对明确的前后两端服务，二者不能混为一谈。E、F、G 是可能的新素材标识，不要求每次恰好生成三个。

各内容块可继续接受情绪演绎：A_e1 表示 A 的情绪版本，A_c1_e2 表示内容变体 A_c1 的情绪 e2 版本，E_e2 则是关联新素材 E 的情绪版本。E 也可继续发展为 E_c1。e 表示情绪目标或参数组合，不是固定音频文件名称。

系统记录参考来源、生成条件、版本和使用位置，按当前作品实际需要生成候选、确认与缓存，不预先穷举全部主题、情绪、变体和连接组合。当前已实现单参考素材的受限内容变体与关联回答句；多参考融合、发展句／对比句及任意风格续写尚未完成。

### 4.3 情绪演绎：跨块统一，而非一块一种情绪

原主题、内容变体与 E、F、G 等关联新素材形成素材池后，用户再设计情绪区间和曲线。系统据此选材并统一编配，而不是简单延长或复制。情绪区间独立于内容块边界：

```text
音乐内容： [ A ][ B ][ A_c1 ][ E ][ C ][ D_c1 ]
情绪区间： [  温暖／希望  ][ 悬疑 ][紧张／危机][振奋]
```

示意中的长度仅用于说明层次，不代表固定小节数。同一情绪覆盖不同内容时仍可以逐渐发展；一个长块也可跨越情绪节点，由系统在内部按乐句安排变化。

可选的表达维度与处理手法包括：

| 情绪维度 | 可控制的音乐变化 |
|---|---|
| 强 → 弱 | 力度、响度、声部数量、鼓组强度和演奏触键 |
| 绵长 → 紧促 | 音符时值、节奏密度、断奏比例和切分程度 |
| 松弛 → 紧张 | 和声稳定性、不协和程度、持续音和节奏推进 |
| 单薄 → 宏大 | 配器层数、音域宽度、合唱与空间混响 |
| 温暖 → 冷峻 | 乐器选择、频谱重心、调式和音色质感 |
| 私密 → 开阔 | 声像宽度、空间感、近场人声与环境混响 |
| 平稳 → 激烈 | BPM、动态变化、鼓点密度和重音位置 |

规划中的处理包括主题变奏、关联新乐句生成、乐器替换、配器增减、和声重配、调式变化、节奏重组、乐句伸缩与过门生成。首版表达标签为平静／安定、温暖／希望、悲伤／失落、悬疑／不安、紧张／危机、振奋／坚定。“高潮”是强度与段落发展目标，不是独立情绪标签；各类情绪均可能有高潮。

手法由系统依据参考素材、当前情绪、变化程度和前后文自动选择并组合，不要求用户执行。上表是候选关系，不是“某乐器必然对应某情绪”的固定公式。

### 4.4 连接关系与过渡块

连接必须同时关联前后两端，可用 T(D_ei → A_ej) 表示从情绪 i 下的 D 到情绪 j 下的 A。处理可以只发生在边界，也可以形成独立的过渡块；每条连接记录可改范围、入出点与时间安排。

连接应参考两端实际音符、和声、配器、节拍及情绪走向。同一情绪内部也可能需要音乐衔接；不同情绪之间也可能无需新增过门。若过渡占用或增加时间，应明确报告其对总时长及后续位置的影响。

### 4.5 双向协作

创作者默认确定主题参考和允许的变化程度，也可对关键表达提出额外保留要求，将具体处理交给系统：

```text
必须保留：主旋律轮廓、核心和弦、第一句人声
允许变化：配器、力度、节奏密度、段落长度
目标变化：克制 → 不安 → 爆发 → 释怀
```

生成后，制作人可以修改具体音符、乐器和自动化参数，也可以只修改情绪线。系统区分修改单个内容块、整个情绪区间和某条连接，并据此计算影响范围。素材池中的主题更新不应静默覆盖已确认的使用版本；需要传播更新时先展示受影响位置。

## 5. 核心功能与开发难度

| 核心功能 | 说明 | 难度 |
|---|---|---:|
| 主题素材与来源关系 | 管理原主题、内容变体、关联新素材及使用版本 | 中高 |
| 关联新素材生成 | 从 A、B、C、D 的音乐语言按需发展 E、F、G，保持相容性及适量新意 | 高 |
| 跨块情绪规划 | 情绪区间与内容分块解耦，对多个块统一规划表达 | 高 |
| 歌曲结构拆分 | 检测 Intro、主歌、副歌、Pre-Chorus、Bridge、Drop、Outro | 高 |
| 音乐积木生成 | 将片段转换成带有 BPM、调性、能量、情绪等属性的积木 | 中高 |
| 高潮与 Hook 评分 | 判断哪些片段最有辨识度和保留价值 | 高 |
| 情绪曲线编辑器 | 通过节点或曲线设计铺垫、低谷、转折和高潮 | 中 |
| 积木智能编排 | 根据时长、情绪曲线和音乐兼容度选择片段并排序 | 高 |
| 自动连接与过渡块 | 根据两端内容规划边界交接或独立过门，同时管理时长与尾音 | 高 |
| 人声冲突处理 | 检测人声重叠，必要时进行 Stem 分离和人声接力 | 高 |
| 局部重新生成 | 锁定满意部分，只重算指定积木或连接 | 中高 |
| 音频渲染与导出 | 统一响度、限制峰值并导出完整音频 | 中 |
| 自然语言控制 | 理解“高潮晚一点”“保留这句歌词”等修改指令 | 中 |
| MIDI 与旋律积木导入 | 读取旋律、和弦、节奏及 Tempo 信息 | 中 |
| 主题变奏与续写 | 在保留辨识度的前提下生成不同情绪版本 | 高 |
| AI 配器 | 根据情绪强度、密度和音色目标分配不同乐器 | 高 |
| DAW 工程交换 | 导入/导出 MIDI、Stems、Tempo Map 和 Marker | 中高 |
| 自适应音乐状态机 | 根据游戏或内容状态实时选择积木与连接 | 高 |

核心 MVP 难度为中高，主要不确定性是约束冲突处理、音乐衔接质量和情绪感知评估。应先验证 MIDI 与预制分轨上的局部编辑，再评估生成模型；完整音频生成、多乐器可控变奏、插件与实时生成属于后续阶段。难度与周期为工程估算，不作成功保证，详见开发计划。

## 6. 预计技术栈

当前已采用 Python 3.9、Tkinter、Mido、NumPy 与 LMMS，全部在本地执行，无生成式 AI 调用或服务器依赖；Windows 分享包使用 PyInstaller 打包。以下扩展技术是候选，不代表已经集成，也不要求同时引入。

| 层级 | 当前实现／后续候选 | 用途与边界 |
|---|---|---|
| 桌面交互 | 当前 Tkinter；后续可评估 React、TypeScript、React Flow、WaveSurfer | 单窗口、音乐块、情绪线、试听；迁移 Web 不是当前前置任务 |
| 工程与任务 | 当前 JSON 快照、文件系统、后台线程；后续 FastAPI、Pydantic、SQLite | 素材、来源、约束、项目版本与渲染任务；并发需求出现后再考虑 Redis／Celery |
| 符号音乐 | 当前 Mido、NumPy；候选 pretty_midi、music21／musicpy | MIDI 解析、音符变换、和弦与伴奏；工具本身不负责情绪决策 |
| 编排与生成 | 当前规则评分与受限搜索；候选 AccoMontage2、REMAST、MuseControlLite | 分别评估伴奏、情绪过渡和可控生成；模型由适配器接入，输出必须通过约束检查 |
| 音频输入分析 | 候选 librosa、Essentia、All-In-One、Demucs、CLAP | 节拍／段落、分轨及特征；自动主旋律提取未完成，分轨不等于识别主旋律 |
| 合成与音频处理 | 当前 LMMS、NumPy；候选 FluidSynth、FFmpeg、Rubber Band、Pedalboard、pyloudnorm | 合成、变速、效果和响度；按需要选用并核对分发许可证 |
| 决策辅助 | 候选 LLM API、OR-Tools | 解析自然语言和约束搜索；不是渲染或音乐质量的保证，规则路径须可独立运行 |
| DAW 与互动媒体 | 当前 MIDI／MMP／WAV；后续 Stems、Tempo Map、Marker、FMOD／Wwise | 先做文件交换与实际导入验收，后做插件和游戏调度；OSC／Link 不替代工程交换 |
| 部署与维护 | 当前 Windows 本地包；后续自动构建、独立模型环境及按需服务化 | 默认不上传用户音乐；模型硬件和跨平台兼容必须实测 |

优先保持现有单机闭环；研究项目的代码、权重、数据许可证与运行环境分别核查。详细参考项目及评估任务见[早期开发与验证计划](EmoBlocks-development-plan.md)，其中的 Web 架构和排期仅供参考。

## 7. 推荐系统架构

以下是完整产品的概念架构，具体 Web 框架和模型不是前置要求。主流程先发展内容素材，再设计情绪线；后续编辑可返回素材阶段补充候选，不改变首次创作的先后顺序，也不要求穷举所有素材版本。

```text
给定主题素材 A、B、C、D
        │
        ▼
内容发展：主题变体 A_c1 等 ＋ 关联新素材 E、F、G
        │
        ▼
形成素材池 → 用户设计情绪区间／曲线
        │
        ├── 可选用的原主题、内容变体与关联新素材
        ├── 目标情绪、强度、主题变化程度
        └── 可选约束、时长、已确认版本
        │
        ▼
统一创作规划器：规则起步，可接入 AI 候选
        │
        ├── 素材池与来源：A_c1 等内容变体、E/F/G 等关联新素材
        ├── 跨块情绪规划：选材、统一配器、和声方向、局部情绪版本
        ├── 连接规划：边界处理或 T(来源块 → 目标块) 过渡块
        ├── 依赖与版本：区间修改、内容更新、连接修复、候选复用
        └── 检查：主题关系、可选锁定、时长、边界和音频安全
        │
        ▼
符号编配／模型候选 → 合成与音频处理 → 连续渲染
        │
        ▼
完整音频 ＋ 可编辑内容 ＋ 情绪路线与生成／修改记录
```

## 8. 使用方向

### 8.1 游戏制作

游戏音频中已有成熟的分段、分层和状态切换机制。制作团队仍需准备探索、战斗和结算等版本、过门及触发规则。EmoBlocks 的目标是降低这些素材的制作和改动成本，并交付可接入现有音频系统的内容。

EmoBlocks 可以让同一个主题随游戏状态连续变化：

```text
探索：钢琴 + 氛围层
发现敌人：加入脉冲和低音
进入战斗：增加鼓组与弦乐节奏
低生命值：提高张力并缩短音符
胜利：回归主旋律的宏大版本
```

系统根据玩家状态、区域、剧情进度和战斗强度，在保持主题一致的前提下实时选择积木、增加乐器层或切换变奏。

### 8.2 社交场景配乐

适用于个人主页、虚拟空间、派对房、语音房、纪念相册和多人互动内容。音乐可以根据在线人数、互动热度、关系变化、礼物事件或用户共同选择的情绪发生变化，而不是循环播放一首固定背景音乐。

例如：新用户进入时增加欢迎动机；互动热度提高时逐层加入节奏与乐器；多人共同回忆时引用参与者选择的音乐积木；活动结束时自动回收主题，形成完整结尾。

### 8.3 电视剧、短剧与漫剧

影视已有定制配乐、分轨编辑和镜头同步工作流。对于依赖曲库或预算有限的短剧、漫剧团队，反复改剪辑后，重新寻找、裁切和调整配乐仍可能耗时。EmoBlocks 重点支持保持主题、重排乐句和修复连接，降低局部改片后的音乐返工量。

EmoBlocks 可以让创作者先标记剧情情绪节点：

```text
平静对话 → 怀疑 → 真相逼近 → 冲突爆发 → 沉默 → 释怀
```

系统使用同一主题的不同配器和变奏连接这些节点，自动调整段落长度以适应镜头，并为对白密集区域降低人声频段或音乐密度。修改剪辑长度后，只需重新伸缩或续写相关积木，不必重新寻找整首配乐。

### 8.4 视频、广告与互动内容

创作者可以把镜头节奏、字幕、转场和关键画面转换成情绪节点。系统自动为不同长度版本生成一致主题的 15 秒、30 秒、60 秒或长视频配乐，并让高潮精确对齐品牌露出、剧情反转或视觉冲击点。

### 8.5 音乐制作与现场演出

制作人可以将 EmoBlocks 用作灵感草图、变奏生成器和结构规划器；现场表演者则可以根据观众反馈选择不同情绪分支，让同一组主题产生不同的演出路径。

## 9. EmoBlocks 改变的核心问题

本项目面向的具体问题是：创作者只有少量主题素材，却需要让它们发展成情绪连续的完整配乐，并在剧情或时长变化后继续修改，而不反复推翻已确认的音乐。

```text
确定主题参考与已确认版本（可选精确锁定）
    ↓
修改音乐块 / 情绪区间 / 连接 / 时长
    ↓
计算受影响范围，检查约束冲突
    ↓
按需发展素材、统一重编受影响区间、修复连接
    ↓
对比试听、验证并导出
```

音乐内容、情绪演绎和连接形成可追溯的生成关系：

```text
主题素材 A、B、C、D
    ├── 复用原主题
    ├── 内容变体 A_c1、D_c1……
    └── 关联新素材 E、F、G……
             ↓
形成素材池，再设计情绪区间／情绪线
             ↓
情绪区间统一编配：A_e1、B_e1、A_c1_e2、E_e2……
             ↓
连接关系 ／ 独立过渡块 T(E_e2 → D_c1_e3)
             ↓
整首作品：保留来源关系，可局部修改与复用
```

它解决的不是单纯“生成更多音乐”，而是让音乐随着故事、互动和情绪连续变化，同时保留统一主题与创作者的个人表达。

### 9.1 创新性分析与已有工作

检索基准：2026-09-14。以下结论来自官方仓库、论文和产品文档，未完成源码复现或模型横向实测；不能据此证明全球首创。

| 已有方向 | 代表工作与证据 | 对创新主张的限制 |
|---|---|---|
| 旋律与情绪曲线生成伴奏 | [Emotion-flow Guided Music Accompaniment Generation，2016](https://dihana.cps.unizar.es/proceedings/ICASSP/2016/pdfs/0000574.pdf) | 画情绪曲线、输入旋律不是新概念 |
| 情绪编曲与平滑连接 | [REMAST，2023](https://github.com/CarlWangChina/REMAST-Real-time-Emotion-based-Music-Arrangement-with-Soft-Transition) | 连续情绪流和柔和过渡已有研究 |
| 乐句选择、结构与疏密控制 | [AccoMontage](https://github.com/zhaojw1998/AccoMontage)、[AccoMontage2](https://github.com/billyblu2000/AccoMontage2) | 分块编排、A/B 结构和伴奏密度控制已有实现 |
| 部分约束下补全 | [Music SketchNet](https://github.com/RetroCirce/Music-SketchNet) | 控制音高、节奏并补全音乐已有先例 |
| 时变条件、局部补全和续写 | [MuseControlLite](https://github.com/fundwotsai2001/MuseControlLite) | 多维可控生成与局部编辑不是独有能力 |
| 节点创作与 DAW 连接 | [Nodal](https://nodalmusic.com/) | 节点、连线、控制曲线及 MIDI 互通已有产品 |
| 互动音乐分段与转场 | [Wwise](https://www.audiokinetic.com/en/public-library/2024.1.8_8893/?id=creating_interactive_music&source=Help) | 游戏自适应音乐不是新赛道 |
| 实时生成与 MIDI/DAW 控制 | [Magenta RealTime 2](https://magenta.withgoogle.com/magenta-realtime-2) | 实时配器控制与 DAW 兼容本身不足以建立创新 |

**拟验证的创新贡献**：在同一套音乐积木表示中，联合管理原主题、内容变体、关联新素材及来源关系，将音乐内容分块与情绪区间解耦，并支持跨块统一编配、局部情绪／时长变更、连接修复与可编辑交付。精确锁定是可选约束，不是默认禁止旋律发展。重点验证能否减少返工和不必要的修改，同时保持主题与听觉连贯性。

上述属于候选产品及工作流创新；新增 E/F/G 生成、情绪跨块或主题变奏本身不据此宣称首创，算法创新仍需具体方法、对照实验与消融验证支持。此处沿用原有研究比较，未因本次设计修改宣称完成新一轮穷尽检索。

不使用“首次实现情绪音乐”“首次分块编曲”或无实证的创新性评分。已有项目是技术基础和对照对象；未见某功能不代表其不存在。

## 10. Hackathon MVP 范围

优先推进原创旋律到完整作品的主线，再扩展歌曲素材入口。以下是产品验证顺序，不意味着所有能力都必须塞入同一次 Hackathon；具体实施以实现目标计划为准。

1. **步骤1，阶段完成**：给定 4～8 小节旋律，自动六情绪编配，支持有限变奏及 MIDI／MMP／WAV 导出。
2. **步骤2，首版完成**：原主题、内容变体与单参考回答句组成素材池，记录来源、候选和版本；听感待验收。
3. **步骤3，首版完成**：固定主题骨架、同来源替换和授权插入，跨块情绪区间、统一编配、边界处理及连续渲染。
4. **交互已交付**：单窗口快速／精细模式，支持多块输入、强度节点拖动和播放块高亮。单旋律快速路径先发展回答句；多旋律路径直接保序使用已给定素材，不自动补段。
5. **下一轮建议**：先验收听感，再实现局部编配保持、依赖范围与缓存；随后评估独立过渡块、块内情绪类别变化和更丰富的候选模型。
6. **后续扩展**：歌曲输入、分轨交付、镜头同步、游戏调度及 7～8 分钟长作品，均需单独验证。

现有演示为 64 秒主体加 1 秒尾音，不据此宣称长作品或专业配乐质量已完成。曲线当前是块／区间级情绪标签与线性强度，不是任意时间连续多维情绪控制。

比赛阶段可以暂时简化：

- 任意复杂的分支图；
- 实时 DJ 演出；
- 完整 AI 作曲；
- 大规模商业曲库接入；
- 所有歌曲的完整 Stem 预处理；
- 过多类型的专业效果器。

## 11. 难度与人员预估

如果团队有 3～4 人，可以按以下方向分工：

| 角色 | 主要任务 |
|---|---|
| 产品与交互 | 情绪积木规则、用户流程、路演与测试 |
| 前端开发 | 积木编辑器、情绪曲线、波形与试听交互 |
| 音频/算法开发 | 结构识别、片段评分、编排和转场策略 |
| 后端/工程开发 | API、任务调度、缓存、音频渲染与部署 |

在受控素材和明确约束下，先争取完成可演示原型。应优先验证：

- 至少一组给定主题的内容分块与来源关系清楚；
- 生成作品具有明确的铺垫、转折和高潮；
- 可以试听并局部替换积木；
- 已确认内容与用户主动锁定的部分是否保持，局部修复相对直接拼接／固定 Crossfade 是否有可测听觉改善。

原排期假设为 3～4 人、有人具备音乐制作经验、使用现成素材与模型，按 4～6 周验证型 MVP 估算；它不覆盖本次新增的完整内容发展与跨块情绪能力，需按实际范围重新估算。48～72 小时比赛适合受控演示，不等同于完成全部能力。当前阶段见[实现目标计划](EmoBlocks-implementation-goals.md)；[早期开发计划](EmoBlocks-development-plan.md)保留资源参考，其中默认锁定、架构与范围表述尚待按本次设计同步。

## 12. 核心验证目标

第一版需要证明的不是系统能否处理所有音乐，而是：

> 普通用户能否通过设计情绪积木和连接创作完整音乐；专业创作者能否保留自己的主题表达，同时利用 AI 快速得到可编辑、可变奏、能够适应不同场景长度和情绪状态的音乐作品。

重点测试：原主题及其变体的辨识度、E/F/G 与参考素材的音乐相容性和新意、跨块情绪统一性、未修改内容稳定、可选锁定保持、连接自然度、修改耗时与人工修正次数。基线包括手工分层配乐、分段独立生成再拼接，以及关闭局部修复的系统版本。实验前不宣称优于这些基线。
