# EmoBlocks 开发计划 r3：先补全、再放置并保护 bridge、最后处理连接

## 1. 主流程与基础要求

新的完整流程为：

**导入原始旋律 → 按块／句生成新旋律 → 绘制强度线并排列素材 → 设置情绪 → 完成补全候选 → 判断 bridge 位置 → 锁定保护范围 → 生成 bridge → 判断并生成连接块 → 最终块间处理 → 编配、试听、确认与导出。**

每套推荐分别执行完整流程。用户试听的是完成 bridge、连接块和块间处理后的效果，确认时应用同一份结果，不重新随机生成。

本计划替代旧规格中的固定 A／B／C／D 版本、先连接后补全、bridge 与连接块共同决策、右栏 BPM 控件及独立记忆点标记。

### 三栏与素材

- 左栏仅显示原始来源、旋律概览和整体试听，可折叠；新旋律直接进入中栏。
- MIDI／MMP 旋律按四拍分块，短尾保留实际长度，保存原始来源、音符快照和跨块音符身份。
- 新旋律按块或乐句生成，不建立固定版本族，不隐式轮换用户选中的素材。
- 导入后默认最多生成三条候选：局部变化、回答句、节奏重组。优先首个有音符完整乐句，否则使用首个有音符块；重复或无效结果不凑数。
- 按需生成支持局部音高变化、回答、原副旋律规则、节奏重组、动机发展、疏密变化及 bridge。副旋律规则生成替换素材，不额外叠加声部。
- 整句作为主要素材，可展开四拍子块；子块可以独立试听、拖用和组合，保留所属乐句、相对位置与来源。
- 中栏卡片尺寸一致，纵向滚动；拖到目标卡左／右决定组合顺序，行内确认后新增素材，取消不修改工程。
- 组合支持重复和嵌套；整句或组合整体放置时使用一个外框、一个情绪。
- 显示编号与内部身份分离；删除不重排已有编号。
- 点击只选择，明确点击播放才试听；所有对象共用底部播放器。
- 保存生成方法、参数、种子、算法版本和基础音符快照，不覆盖素材原件。

### 时间轴、情绪与记忆

- 默认八个四拍格、内部 120 BPM、初始强度 0.25，不自动填入素材。右栏移除 BPM 控件，本轮不另增速度入口。
- 使用一张二维强度画布：宽度表达实际时长、厚度固定、中心高度读取中点强度。
- 用户拖放每拍吸附；自动补全允许按精确 tick 边界处理不足一拍的空缺。
- 移动和删除不压缩时间轴；重叠、越界及截断已有内容的缩短操作必须拒绝。
- 移动积木不移动强度线，纵向拖动不直接改变强度。
- 保留当前无过冲的平滑强度插值，增加手绘转控制点；一次手绘一次撤销，Esc 取消未提交操作。
- 点击积木展开行内情绪选项，取消涂色情绪画笔，新放置默认平静。
- 情绪处理从每次放置的基础快照重新计算，不累计失真，不影响素材库或其他使用。
- 自动峰值所在音乐块上叠放“记忆积木”，不增加时长或音符。相同峰值取最早位置，作品终点映射最后有效片段。
- 记忆保护所选素材在情绪处理前的音高和节奏，不恢复为原始来源旋律。
- 长句／组合只保护对应四拍子片段，短尾按实际长度；标记位置与保护范围一致。
- 峰值为空缺时待落位，峰值在主动留白时保留留白。
- 待补全空缺、主动留白、素材自身休止分别表达。主动留白禁止主旋律，允许克制伴奏及自然尾音。

### 技术与视觉

继续使用 Python/Tk、共享前端和 Mac／Windows 配对适配器。保留保存、撤销、历史成品、整曲编配、MIDI／MMP、LMMS 连续 WAV 渲染及尾音处理。

- 明亮模式采用 Soft UI：柔和浅底、低饱和色、圆角和软阴影。
- 黑暗模式采用静态 macOS Vibrancy：`#1c1c1e`、`#2c2c2e`、`#3a3a3c`，1px 边框，最大 12px 圆角，`#0a84ff` 交互强调，无渐变、发光或装饰动画。
- 情绪颜色为语义例外，正文对比度满足 AA。
- 最小窗口 1020×700，窄窗口优先收起来源栏；中栏纵向滚动，画布横向滚动。
- 说明支持悬停和键盘焦点，错误、生成状态及待补全状态直接显示。
- 当前编辑、播放对象、选中成品和导出对象明确区分。
- 撤下精细创作入口；旧工程保留读取及已有成品试听、导出，不自动迁移为可完整编辑的新工程。
- 哼唱和外部模型本轮仅预留接口，不安装模型。

## 2. 补全、bridge 与连接的严格顺序

### 阶段 A：完成基础补全候选

补全先形成具有实际素材和音符快照的候选排布，再交给 bridge 阶段。

- 选中空缺时只处理该处，否则处理全部空缺。
- 同时考虑左右音乐关系、实际长度、调性、节奏、动机、情绪、强度和整体重复。
- 可以使用原始素材、已有新旋律，或生成精确长度的新素材。
- 此阶段不决定自动 bridge 的位置，也不预留无音符的 bridge／连接块占位。
- 候选的目标空缺必须已解决；素材内部休止合法，不能将剩余空缺偷偷改为留白。
- 没有合法填法时报告失败或候选不足，不进入后续处理。
- 补全只改变目标空缺的基础排布，不移动或改写已有放置。
- 峰值空缺获得基础素材后，立即确定该候选的记忆保护，再进入 bridge 判断。

局部补全不处理其他空缺；其他空缺仍明确标为未完成，不能据此导出正式整曲。已经完整摆放的工程直接使用当前排布进入 bridge 判断。

### 阶段 B：判断 bridge 位置

基于完成后的候选排布，判断哪里适合用 bridge 替换基础旋律。

候选区域包括两段重要旋律之间连续两至四块或更长的范围。连续同情绪只是参考，不是强制条件。

决策顺序：

1. 检查已有音乐是否已经自然成立。
2. 分析前后动机、调性、节奏、情绪与强度发展。
3. 判断是否需要具有内部发展的桥接乐句。
4. 排除违反记忆、主题、手工修改和固定时间约束的范围。
5. 比较保留原排布与采用 bridge 的收益。
6. 确定 bridge 的位置、长度、上下文和生成目标；允许选择“不使用 bridge”。

遇到记忆、主题或手工保护区时，调整或放弃候选窗口，不移动这些保护区。主动留白可作为 bridge 内部的休止，但必须原样保留主旋律空白。

用户明确拖入的 bridge 素材视为已确定位置，提前登记保护；自动规划不能再将它覆盖。其上下文适配性仍需检查。

### 阶段 C：锁定 bridge 范围并生成内容

**位置一旦确定，立即建立保护记录，然后生成 bridge。**

保护分为两个状态：

| 状态 | 含义 |
|---|---|
| 范围已锁定 | 起止时间、所有者、输入快照和计划版本已确定，其他生成器不能占用 |
| 内容已就绪 | Bridge 生成并通过验证，保存实际音符快照及旋律结构指纹 |

Bridge 使用统一新旋律服务生成，输入包括左右素材、长度、调性、情绪与强度轨迹、保护范围和留白掩码。

Bridge 应具有动机联系、乐句发展和目标入口空间，不能只是加长的首尾音插值。缺少一侧素材时，按单侧引入或收束处理，不能假定存在双侧上下文。

情绪处理在 bridge 内容就绪前完成，避免后续再次累计处理。相邻 bridge 缺少实际端点时，先联合确定边界条件，再生成，不能互相读取旧音符猜测。

**连接块判断必须等待所有选定 bridge 内容就绪。**

Bridge 生成失败时：

- 保留原始补全候选和已有工程。
- 当前处理结果不得进入连接块阶段。
- 不静默解除锁定，让连接块占用失败范围。
- 重新选择位置或改为“不使用 bridge”必须创建新的计划版本，并重新执行后续阶段。

保护针对后续自动处理，不禁止用户明确移动、删除或重新生成 bridge；用户操作必须更新保护记录并使依赖结果失效。

### 阶段 D：判断并生成连接块

连接块规划读取的是**已经包含 bridge 的实际音乐排布**。

可用窗口为允许修改的范围减去：

- Bridge 锁定范围；
- 记忆、主题与手工保护范围；
- 主动留白中禁止生成主旋律的范围；
- 已分配给其他连接块的范围。

必须先判断是否需要连接块，再选择窗口和规则，不能只依据情绪变化自动增加内容。

- 规则可复用调内导向、局部回应、铺垫、先保留后展开及结尾收束。
- 使用实际 bridge 首尾音和相邻素材音符，不使用被替换前的旧端点。
- 窗口与 bridge 相交时，该窗口无效；重新搜索合法窗口，不能裁切或覆盖 bridge。
- 连接块之间不得重复覆盖；相邻待生成连接块先确定依赖与共享边界。
- 没有合法窗口时保留现有旋律，退回轻量块间处理。
- 不能移动素材、延长作品或改变用户设定的情绪位置。

生成结果保存为覆盖层，基础排布不被销毁，支持对比试听和撤销。补全写入范围、bridge 范围和连接块影响范围分别记录。

### 阶段 E：最终块间处理

在 bridge 和连接块均已完成后，处理最终音乐边界：

| 类型 | 处理目标 |
|---|---|
| 自然延续 | 保留主体，通过奏法、力度、和声或音色交接维持连续 |
| 动机回应 | 在允许范围内用节奏或音程回应加强关联 |
| 渐进铺垫 | 为目标变化准备空间，避免抢占目标旋律 |
| 留白进入 | 利用句尾、休止、减层或弱起形成清晰入口 |
| 回落收束 | 降低密度和张力，符合条件时形成稳定结束 |
| 无专门处理 | 已有音乐成立，保持原状 |

这些类型只用于最终边界处理，不替代 bridge 或连接块生成。

**Bridge 的保护在该阶段继续有效：**

- 不改变其音高、起点、时值，不在其范围新增主旋律音符。
- 可以在保护区外调整邻接片段，也可进行不改写主旋律的力度、音色及伴奏交接。
- 不因缺少连接空间反向缩短 bridge。
- 乐句内部四拍分界不自动触发过渡。
- 仅合并确属同一来源音符的连续切片。
- 鼓组填充和目标音预示不是默认动作。
- 边界操作先收集，再统一检查冲突，避免顺序执行造成重复覆盖。

最终校验必须重新检查所有保护范围，不能只信任各生成器自己的声明。

### 阶段 F：推荐、试听与应用

每个候选完整执行 A–E，再进行编配和试听准备。

- 至少两套在音符、节奏、排布或乐句结构上有实际差异的有效方案；不足时如实说明。
- 不同名称、编号、种子或情绪标签不能代替实际音乐差异。
- 试听包含 bridge、连接块和最终块间效果，并支持与基础排布对比。
- 确认使用同一份试听快照，不重新随机生成。
- 自动补全运行相同流程，应用排序最高的有效方案。
- 候选中的新素材确认后才加入工程及中栏，取消不污染素材库。
- 基础补全、bridge、连接覆盖和新素材的应用是一笔事务，一次撤销完整恢复。
- 用户修改相关素材、位置、情绪、强度或长度后，使依赖它们的旧计划失效。
- 失效意味着需要重新计算，不能变成“允许旧连接块侵入 bridge”的授权。

最终编配继续根据情绪和强度处理音色、力度、和声、低音、节奏及条件鼓组，同时遵守留白和连接计划。

“仅主旋律”关闭伴奏、统一旋律音色和力度，但保留已确定的旋律及连接。MIDI／MMP／WAV 来自同一整曲乐谱，音乐主体长度与音频尾音长度分别记录。

## 3. 后端接口、保护与状态

内层格式继续采用 `emoblocks.assembly.v2`。规格修订号统一为：

`SPEC_REV=curve-workflow-v2-r3`

音乐时间使用整数 tick，`PPQ=480`，区间为半开区间。公开接口采用可序列化纯数据，不依赖 Tk、像素坐标或播放器句柄。

| 对象／接口 | 必须表达的内容 |
|---|---|
| 素材与乐句 | 身份、长度、音符快照、来源、生成方法、乐句及子块关系 |
| 固定时间轴 | 总长度、独立放置、基础快照、情绪、强度和主动留白 |
| CompletedCandidate | 已完成目标补全的基础排布、实际音符、保护信息及输入指纹 |
| BridgePlan | 位置、长度、上下文、选择理由、计划版本；也可明确无 bridge |
| BridgeProtection | Bridge 身份、锁定范围、输入版本、锁定／就绪状态及内容指纹 |
| BridgeResult | 完整乐句、子块、来源、生成参数、实际音符及保护校验 |
| ConnectionBlockPlan | Bridge 版本与保护摘要、合法窗口、实际端点及生成规则 |
| BoundaryPlan | 最终相邻对象、局部操作及不得改写的范围 |
| AuditionCandidate | 完整乐谱、各阶段结果、对比快照、应用事务及输入版本 |

### 三道后端检查

1. **规划前检查：** 连接块接口拒绝 bridge 未就绪或版本不匹配的输入。
2. **生成后检查：** 连接块不能在 bridge 范围内写入主旋律。
3. **整曲检查：** 最终 bridge 的旋律结构与锁定内容一致，允许的表演和编配变化单独记录。

保护信息随保存、撤销、推荐和生成快照持久化，不能只是 Canvas 标记。

后台任务绑定输入快照与请求身份。失败不能部分写入工程，过期结果不能覆盖当前编辑，试听准备完成不能自动抢占播放。

播放位置、选择、悬停、滚动和主题不影响音乐内容指纹。保存状态、生成状态和当前所选成品状态分别判断。

旧格式使用独立读取路径；新流程不能重新调用会隐式轮换固定版本的旧规划逻辑。

复用现有基线和工作目录，不重复初始化或覆盖其他任务。P0–P1 由负责人主导，其他角色只执行明确派发的设计审查；契约与基础后端通过后，再按文件归属并行开发。

### herdr 交接规则

- 操作 herdr 前确认 `HERDR_ENV=1`，依据本机帮助和真实返回核实角色及 pane。
- 每个任务包含 `RUN_ID、TASK_ID、ROUND、SPEC_REV、CONTRACT_REV、WORKTREE、BASE_SHA`，以及允许文件、依赖和验收条件。
- Worker 只提交自己的任务范围，不合并集成分支、不推送、不互相派单。
- 负责人读取各 pane 结果；空闲状态不等于通过，超时先读输出，不盲目重发任务。
- 每阶段按“实现 → 集成 → 冻结 → 独立验证 → 修复复验”执行，最多五轮。
- Verifier 检查前后核对代码指纹；受检代码变化则本轮结果作废。
- 验证期间停止修改集成目录，音频设备检查串行执行。
- 运行记录与动态映射保存在仓库外，不污染代码指纹。
- 首次执行止于 P0–P1 汇报，后续分阶段启动；不自动推送或发布。

## 5. 测试与验收标准

### 基础工作流

- 四拍分块、短尾、跨块长音、多来源、重复和嵌套组合。
- 整句展开后子块独立拖用，乐句及来源关系完整。
- 固定长度上的放置、移动、删除、越界和重叠拒绝。
- 2.5 拍素材后留下的 0.5 拍空缺可精确补齐，原素材及后续素材不移动。
- 手绘和控制点编辑、取消、一次撤销、滚动缩放后的命中。
- 同一素材多次使用的情绪独立，记忆保护当前所选素材。
- 保存重开、旧工程读取、失败恢复及过期任务处理。

### Bridge 顺序与保护

- 补全尚未完成时不能调用自动 bridge 位置决策。
- Bridge 位置确定后、生成尚未结束时，保护记录已经存在。
- Bridge 未就绪时不能开始连接块判断。
- 完全覆盖、部分侵入或跨越 bridge 的连接窗口必须拒绝。
- 不允许通过缩短、裁切 bridge 为连接块腾出空间。
- Bridge 两侧均需要连接、没有合法窗口、多个 bridge 相邻或生成失败时，保护仍成立。
- 连接块使用实际 bridge 首尾音，而非被替换前的端点。
- 最终块间处理不能修改 bridge 的旋律结构，合法力度与配器变化单独验证。
- 手动放置、移动、删除 bridge 后，保护范围和依赖结果正确更新。
- 记忆、主题、手工修改和主动留白优先于 bridge 选择。
- Bridge 失败不能静默解锁；新位置或无 bridge 方案必须使用新的计划版本。
- 保存、撤销、推荐应用和后台返回均保持正确保护关系。

### 推荐与真实输出

- 推荐至少两套实际音乐不同的有效方案，或明确说明不足。
- 试听不改工程，应用与试听一致，一次撤销恢复全部相关状态。
- 没有待生成占位被误报为完成。
- 乐句内部四拍边界不重复添加过渡，来源不同的同音高音符不误合并。
- 使用固定素材提供基础排布、bridge 后、连接块后和最终版本的对照试听及影响范围。

按改动运行后端测试、完整测试、双前端契约检查和差异检查，完成实际 LMMS 连续渲染、保存重开及 MIDI／MMP／WAV 输出验证。

检查两种主题、1020×700及较大窗口、来源折叠、Mac 触控板与鼠标、Windows 对应交互和常用缩放。

验收报告分别记录自动约束检查、程序化 Tk、真实渲染、实际设备播放、Mac／Windows 实机和人工听感。自动测试通过不能替代连接自然性与音乐表达的人工验收。
