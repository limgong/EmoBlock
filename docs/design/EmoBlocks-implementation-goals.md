## 最新增补：拍级情绪线适配

### 1. 目标

将块内控制从整小节细化至整数拍节点，支持不同情绪位置与强度发展，不改变素材、结构或时长。

### 2. 选择原因（概述）

体现“情绪变化不受小节边界限制”的工作流。先使用明确拍网格，避免同时引入自由时间、变速与情绪混合模型；仅检查功能闭环。

### 3. 表达方式

选择块 → 填写拍号／情绪／强度，或点图定位 → 添加／更新／删除节点 → 完整生成或预览局部影响后生成。起点和终点保留；终点位于最后一拍之后，不增加时长。播放显示当前块、拍、情绪与目标强度。

### 4. 实现手段与状态

表达数据增加可选 beat_nodes。节点间线性插值强度，类别在节点处切换；逐拍采样驱动配器、力度及节奏，和弦仍按小节规划。旋律起音、时长与音高保持，持续音不强制截断。旧整块／小节工程兼容。

拍级与小节细分互斥，切换前要求整块重置；编辑可撤销，设置进入工程和播放快照。局部修改仍以整个目标块及必要邻接范围为单位，不宣称仅重编所选拍。

新增 9 项测试，总计 115 项通过；完成 jybd 实际局部 WAV／MIDI／MMP、保存重开、节点删除撤销和同一小节内播放情绪切换。暂不实现拍内小数位置、情绪连续混合和连续音量自动化；原压缩包未更新。

## 最新增补：块内情绪变化

### 1. 目标

同一块内按小节设置不同情绪及强度，不改变块身份、旋律、时长与结构，并贯通显示、生成、局部修改、撤销、保存和播放。

### 2. 选择原因（概述）

打通“一个内容块经历多种情绪”的流程，不再要求换情绪就拆块。首版使用小节网格，不增加自由时间编辑与模型推理复杂度，不设置生成质量评价门槛。

### 3. 表达方式

精细创作的“情绪与连接”页中选择块、块内起止小节、情绪和强度并应用，可重复设置多个区间。曲线显示细分色带，下方列出逐小节设置；播放显示所选历史结果的当前小节与情绪。原有整块应用会覆盖所选块细分设置，提示并支持撤销。

### 4. 实现手段与状态

表达数据增加可选逐小节设置，旧工程自动沿用原整块标签和强度线；逐小节读取和声、配器、密度及力度目标，强度使用小节中点。块内情绪类别边界复用连接处理，不增加小节；持续主旋律不因边界被截断。

局部修改通过表达快照差异识别目标块，仍按整块及必要邻接边界更新；没有缩小为仅选中小节的局部缓存。支持独立过门的块内变化、保存重开、撤销和结果播放快照。

8 项新增测试、总计 106 项自动测试通过；使用 jybd 完成实际局部音频生成与设备播放情绪切换。任意拍点／连续多维情绪控制后置。旧程序及文档压缩包未更新。

## 最新增补：独立过渡块

### 1. 目标

将连接从既有块边界上的处理扩展为独立、有明确长度的过门 `T(A → B)`，同时维护主题顺序、时间线、情绪设置、播放定位和导出。

### 2. 选择原因（概述）

补齐“选择连接位置 → 自动生成过门 → 调整／撤销 → 输出”的工作流。过门服务指定两端，不与可独立复用的关联素材 E 混淆。

### 3. 表达方式

精细模式结构页选中前块 → 选择 1／2 小节 → 在选中块后生成 → 情绪与连接页调整表达并完整生成。显示 `T(前块 → 后块)`，播放时单独高亮；支持移除、撤销和工程恢复。

### 4. 实现手段与状态

结构新增 transition 实例，绑定前后排列 ID、长度和生成器版本；根据实际两端音符和调性参考确定性生成逐拍连接旋律，进入同一和声／配器与渲染链。过门初始强度衔接两侧，标签默认跟随后块；后续作为独立情绪块编辑。

首版只增加时长并顺延，不挤占既有小节，不改变原骨架。边界连接开关不删除独立过门；端点替换读取新内容，破坏相邻关系的编辑被拒绝并提示先移除过门。结构变化后完整生成新基准，再继续局部情绪修改。

新增 9 项自动测试，合计 98 项通过；实际使用 jybd 两段完成 WAV／MIDI／MMP 渲染、时长检查、过门播放定位、保存重开与局部修改预览。尚不包括固定总长、任意长度、过门模型候选或块内情绪类别变化。只验工作流，不设生成质量验收门槛；旧压缩包未更新。

## 最新增补：局部情绪修改与保留

### 1. 目标

对已生成作品修改部分块的情绪，更新目标块和必要连接，保留范围外已确认的音符及编配，支持影响预览、历史试听与撤回。

### 2. 选择原因（概述）

补齐“生成 → 局部调整 → 保留／撤回”的编辑闭环。仅验证工作流、结构约束和数据保持，不评价音乐生成质量；不引入新模型或音源。

### 3. 表达方式

右侧选基准结果 → 精细模式应用情绪修改 → 预览局部影响 → 确认生成 → 试听新旧版本或撤回基准。显示目标块、边界块、实际小节范围及保留事件数；普通编辑撤销仍保留。

### 4. 实现手段与完成状态

已实现 `local_engine.py`：读取基准结构与音符快照；检查结构、素材、速度、长度和连接开关一致；为目标块及必要相邻边界规划候选，冻结范围外和弦并复用原音符／声部设置。跨边界延音扩展至完整事件，预览后再提交；结果记录基准、范围和保持校验。

新结果另存，旧文件不覆盖；支持工程保存重开、链式局部修改、撤回基准及撤销恢复。情绪或基准改变使旧预览失效；缺失基准或结构变化明确要求完整生成新基准。

## 步骤1：单个音乐块的可控情绪改变

> 状态：阶段完成（本地规则原型），更新于 2026-09-17。已跑通自动编配、桌面操作和音频／工程导出；不代表音乐听感、模型能力或完整产品已经验收。

### 1. 目标

面向游戏、影视等戏剧配乐场景，输入一段用户给定的 4～8 小节 MIDI 旋律，自动生成符合指定情绪的音乐块，支持试听、换一个候选及继续编辑。

当前是“确定参考旋律”，不是逐音符严格锁定。系统保留可辨认的主题特征，根据用户选择的变化程度，允许适度改变音高、节奏、装饰或句尾。用户无需逐轨编配、手工选择和弦或执行处理手法。

第一版支持六种配乐表达：平静／安定、温暖／希望、悲伤／失落、悬疑／不安、紧张／危机、振奋／坚定。单块可独立生成；存在前后块时，自动参考其情绪与可获得的音乐信息。此处先实现上下文感知的块内编配，不把完整情绪曲线编辑器、任意跨调连接及实时游戏播放纳入步骤1。

当前先做“给定 MIDI”；WAV 旋律提取、复杂混音重编与真正的歌声合成暂不纳入首版。

### 2. 选择原因（概述）

六种表达覆盖低到高强度、积极与消极、稳定与不稳定的戏剧需求，既能形成明显对比，也便于控制初期实现范围。先以给定 MIDI 降低旋律识别的不确定性，将工作集中在自动编配与主题变奏。

情绪、强度、主题变化程度分别控制。“高潮”属于段落发展与强度目标，不是独立情绪；悲伤、危机和振奋都可以达到高潮。

> 注：十种候选的取舍与六种表达的区分见附录“问题分析 B”；规则和 AI 的分工、上下文示例及工具边界见“问题分析 C”。早期关于严格锁定的讨论保留在附录 A、D，不再作为默认要求。

### 3. 表达方式

#### 用户如何选择

用户提供或指定参考旋律，选择目标情绪、表达强度与主题变化程度，随后由系统自动生成。可试听、重新生成或进入编辑器精修，但手工编配不是完成任务的必要步骤。

有前后块时，系统自动读取上下文；缺少上下文时，按独立完整片段处理，不阻塞生成。默认沿用输入速度；若候选涉及变速、移调等明显改变，应在结果说明中呈现，不将加速作为情绪变化的唯一手段。

#### 六种表达的候选手法

下表是系统可选择的手法范围，不是每次必须同时执行的固定配方；具体搭配需结合旋律、强度、前后文及音色资源决定。

| 表达 | 常用候选手法 | 上下文判断重点 |
|---|---|---|
| 平静／安定 | 稀疏伴奏、长音铺底、缓慢琶音、平稳低音、缓慢换和弦、柔和起音、句间留白 | 是安全稳定、冲突后的平复，还是危险前的表面平静？决定是否保留悬置或引入微弱脉冲 |
| 温暖／希望 | 流动分解和弦、平滑声部连接、舒展的和弦排列、柔和回应、逐层进入、适量上行发展 | 从悲伤转来时逐渐明亮；通向振奋时适度增加推动，避免只机械切换大调 |
| 悲伤／失落 | 稀疏节奏、较长呼吸、声部撤出、柔暗音色、延留与缓慢解决、下行伴奏、局部句尾延长或收缩 | 是无力的失落还是强烈悲恸？前者可减法处理，后者也可增强编制与力度 |
| 悬疑／不安 | 持续低音、少量重复音型、延迟解决、稀疏不规则回应、拉开音域、轻度不协和、片段化与留白 | 未知感继续累积还是即将揭晓？末尾维持悬置，或准备解决与后续进入 |
| 紧张／危机 | 低音脉冲、伴奏加密、明确重音、短促发音、打击乐与声部叠加、和声推进或持续悬置、短填充及短暂撤空 | 危机升级、解除还是转为失落？分别准备继续累积、释放或抽离力量 |
| 振奋／坚定 | 稳定节拍、有方向的低音、齐奏与八度叠奏、宽和弦排列、上行发展、回应句、和声解决与强拍落点 | 是刚下定决心还是已经获胜？前者保留动力，后者可更充分终止与释放 |

音色是候选资源而非情绪标签：钢琴不必然平静，铜管不必然振奋；同一乐器可在不同音区、力度和配器关系中产生不同表达。

### 4. 实现手段

#### 首版六项自动能力

1. 自动配和弦与基础伴奏。
2. 自动选择乐器并按乐句安排接力。
3. 自动安排声部逐层进入、退出。
4. 自动改变琶音、脉冲、鼓与低音的节奏密度。
5. 自动生成短句回应及少量句尾变奏。
6. 自动处理力度、音色与空间效果。

以上能力由同一个编配计划协同调用，用户无需逐项操作。复杂对位、大幅主题变形与歌词演唱先后置。

#### 判断与执行的分工

第一版采用“上下文规则规划 → 候选生成 → 确定性执行与检查”。情绪基础方案、上下文评分和约束首先用规则实现，预留 AI 规划及音乐生成模型接口；不能将尚未接入的 AI 判断描述为已完成能力。

| 环节 | 首版实现方式 | 职责 |
|---|---|---|
| 输入与约束 | 确定性程序 | 读取音符、节拍和范围，检查乐器音域、资源、长度及允许的变化程度 |
| 基础手法范围 | 多套规则与模板 | 为每种情绪提供候选，避免一个标签只对应一个固定配方 |
| 上下文规划 | 规则评分起步，预留 AI 规划接口 | 结合当前旋律、目标强度与前后块，选择累积／释放、配器顺序和句尾方向 |
| 内容生成 | 规则生成作为基础，模型候选逐步接入 | 产生和弦、伴奏、回应与局部变奏；模型失败时保留可用回退 |
| 执行与验证 | 确定性程序 | 写入音乐事件、调用音色、渲染并检查越界、缺失资源与时间错误 |
| 表达验收 | 试听为主、指标辅助 | 判断情绪是否可辨认、主题是否仍可识别、前后关系是否自然 |

参考上下文不等于必须使用 AI。后续 AI 适合提出受约束的编配计划或候选，但仍由程序检查和执行，不直接绕过音乐范围与文件安全检查。

#### 工具采用方向与验收

基础音乐操作可选 music21／musicpy；自动伴奏先比较 MMA 的规则路线与 AccoMontage2 的模型路线；音色渲染先沿用已跑通的 LMMS。GETMusic、Music SketchNet 等作为后续候选，不要求首版同时接入全部项目。

用多段旋律验证：同一套程序无需逐首重写规则即可生成六种表达；用户无需手工编配即可完成任务；主题仍可辨认。检查单块生成及有前后文时的结果差异，并以试听判断有效性，不把响度增加或无削波直接等同于情绪正确。

|---|---|
| 旋律输入 | 支持 MIDI type 0/1 与未压缩 LMMS MMP；多轨由用户指定旋律，支持固定 4/4、40～220 BPM、4～8 小节；不支持的输入明确提示 |
| 六种情绪与参数 | 六种表达均可生成；可选择强度、主题变化程度，重新生成不同候选 |
| 和弦与伴奏 | 根据旋律进行启发式调性估计与逐小节和弦评分，生成低音、铺底、琶音／脉冲及适用的鼓轨 |
| 配器与层次 | 使用合成音色预设，自动进行主奏接力、声部进入退出、节奏密度和力度变化 |
| 回应与变奏 | 在已有空隙中生成短回应；按变化程度对部分短句尾音进行邻近和弦音改写；不保证每次都有适用位置 |
| 上下文 | 可选择前后情绪或读取已有结果报告；规则据此调整块内力度包络、末尾密度及和声倾向；尚未读取相邻块实际音符与和声 |
| 声音与导出 | LMMS 离线渲染，加简单立体声短回声；输出试听 WAV、原始 WAV、多轨 MIDI、可编辑 MMP 和处理报告 |
| 可追溯与输入保护 | 记录参数、随机种子、来源哈希、和弦及变奏位置；相同输入与参数可复现编配；每次另存，不覆盖输入 |

实际实现采用 Python／Tkinter、Mido、NumPy 与 LMMS。前文 music21、musicpy、MMA、AccoMontage2 等仍是候选路线，未部署；当前没有生成式 AI 调用。

验证记录：19 项自动测试通过；四段旋律分别生成六种情绪，共 24 次实际渲染通过，结果非静音且未检测到削波样本；桌面“导入 → 生成 → 可试听与编辑”流程通过，并完成高 DPI 显示检查。详见[验收记录](EmoBlocks-Step1/VERIFICATION.md)及[渲染数据](EmoBlocks-Step1/verification.json)。

待继续验证：六种情绪的可辨认性、主题保留程度、和声自然度、音色质量及真实剧情适用性。上述技术检查不等同于听感合格；规则效果若明显不成立，应先修正对应规则，再进入连接试听。

未完成且不在本阶段完成声明内：WAV 提取、复杂混音重编、变速变拍、真实乐器音源、歌声合成、生成模型接入、多块自动连接及局部重生成。

## 步骤2：主题素材池与内容发展

> 状态：首版规则 Demo 已实现，工程闭环通过，音乐听感待验收；更新于 2026-09-17。步骤1解决“给定旋律如何演绎情绪”；步骤2补齐“有哪些可用的音乐内容”，为之后设计情绪线与连续编排提供基础。此处不宣称完整内容发展能力已经完成。

### 1. 目标

将用户给定的主题旋律整理为可独立使用的 A、B、C、D 等内容块，自动产生可辨认的内容变体，并尝试生成与原主题相关的新乐句，形成可试听、可选择、可追溯、可保存的素材池。

本阶段的最小闭环是：**导入或确认主题分块 → 生成内容变体及一种关联新乐句候选 → 对照试听并保留 → 保存素材池**。A/B/C/D 和 E/F/G 是示意编号，不要求用户必须给四段，也不要求一次生成三段新旋律。首轮可用两个主题块 A、B，生成 A_c1 与回答句 E 完成验证。

首次创作顺序固定为：**主题素材 → 内容发展与关联新素材 E/F/G → 素材池 → 设计情绪线 → 跨块编配与连接 → 完整作品**。步骤1已完成的情绪引擎之后复用，不意味着用户需要先给每个素材指定情绪。

### 2. 选择原因（概述）

直接连接“同一旋律的几个情绪版本”，只能演示编曲变化，无法验证最新设计中的多主题、内容发展和关联素材复用。应先将音乐内容与情绪演绎分开，并及早验证“新乐句既有关联、又不是简单重复”这一较高风险能力。

本步骤不同时承担完整作曲与情绪曲线：先验证一种新乐句用途，再拓展发展句、对比句及更多 E/F/G 候选。单块情绪听感仍需继续评估，但不是生成素材池时的必选参数。

> 注：本次取舍与难点见附录“问题分析 F”；原步骤2正文移至“历史记录 G”，原连接分析 E 保留，供后续连接阶段参考，不再作为当前步骤2要求。

### 3. 表达方式

界面先用简单素材列表或卡片，不建设复杂时间线。每个素材显示名称、类型、长度、来源、版本，并提供原旋律试听、候选对照、保留、重新生成和导出。

| 类型 | 示例 | 本阶段含义 |
|---|---|---|
| 原主题 | A、B、C、D | 用户给定并确认的独立乐句；可来自不同文件或同一文件的不同小节范围 |
| 内容变体 | A_c1、B_c1 | 对主题的动机、节奏、轮廓或句尾进行有限发展，仍能辨认原主题 |
| 关联新素材 | E，后续扩展 F/G | 参考原主题音乐语言形成可独立使用的新乐句；首轮只做回答句 |
| 情绪演绎 | A_e1、A_c1_e2、E_e2 | 后续对素材施加情绪的结果，不与内容变体混为一类 |
| 连接／过渡 | 连接关系或 T(A_e1 → E_e2) | 依赖两端内容的处理，留待连接阶段，不以 E 代替过门 |

用户先选择参考素材和“内容变体／回答句”，由系统自动提出候选；不要求用户逐音符填写新旋律、手选和弦或编配。候选默认使用相同中性音色试听，避免把换音色或变响误判为内容发展。允许人工选择喜欢的结果，但不把人工改写作为自动生成成功的前提。

关联新素材不需要预先指定情绪线。之后，一个情绪区间可以覆盖 A、B、E 等多个块；同一个素材也可在不同情绪区间复用。素材本身不永久绑定某种情绪。

### 4. 实现手段

1. **来源与版本。** 记录素材 ID、父素材／版本、选区、音符、速度、调性、参数及种子；素材、情绪演绎和时间线实例分开管理。
2. **给定分块。** 导入 MIDI／受支持 MMP 或选择整小节范围；每块 4～8 小节，固定 4/4，同池统一 BPM 与调性参考。自动分句、任意长输入和短块另行验证。
3. **有限内容变体。** 动机发展、局部模进、节奏重组及句尾改写，检查长度、音域与辨识度；复制、整体移调、换音色不算有意义的新变体。
4. **关联回答句。** 首版参考一个素材，以节奏动机、调内和声、音程与轮廓约束搜索多个候选；不是多参考融合或任意风格续写模型。
5. **筛选与回退。** 检查越界、长度、异常跳进、重复度和动机关系；无合格候选时提示并保留原素材，不能以复制冒充新素材。规则通过不代替试听。
6. **保存与导出。** 复用 Mido、音符结构和 LMMS；保存素材池与中性试听，导出 MIDI／MMP／WAV。另存快照，重生成不覆盖其他素材，不穷举全部情绪与连接组合。
7. **实施顺序。** 导入与保存 → 内容变体 → 回答句 → 对照试听与版本保护；先沿用本地程序，不同时迁移 Web 或部署服务器。

阶段验收：

- 至少用两组不同的给定主题测试，均可形成含原主题、内容变体和回答句候选的素材池，无需为每组重写生成代码。
- 用户无需手写新乐句即可生成、对照试听、保留和重新打开结果；输出长度、音符范围及来源关系可检查。
- 中性音色对照试听中，内容变体仍有主题辨识度；回答句与原素材有关联且不只是复制／整体移调。记录用户的接受、拒绝及原因，不将规则检查通过等同于音乐质量通过。
- 重新生成一个候选不会改变其他已确认素材；原始输入不被覆盖。
- 若回答句始终只能得到机械重复或不相容结果，则仅标记“素材管理与变体部分完成”，不宣称整个步骤2完成。

#### 当前实现进度：独立程序与整体交接已跑通

保留[步骤一](EmoBlocks-Step1/README.md)、[步骤二](EmoBlocks-Step2/README.md)两个独立程序；日常使用[单窗口工作室](EmoBlocks/README.md)，在同一界面完成交接，不再启动另一工作窗口。源码仍复用相邻目录的引擎与资源。

| 环节 | 首版实际实现与边界 |
|---|---|
| 主题导入 | MIDI／未压缩 MMP，选择旋律轨及整小节范围，单块 4～8 小节；同池统一速度和调性参考 |
| 单声部整理 | 默认拒绝同时起音的多声部；用户可明确选择保留高音或低音，并可截短重叠尾音，所有删减记录，不声称自动识别主旋律 |
| 内容变体 | 保留首小节，后续局部模进或节奏拆分，再调整句尾；不是完整结构发展或任意变奏模型 |
| 关联回答句 | 一次参考一个素材，重组其节奏动机，结合调内和声框架、音程倾向、轮廓及受约束搜索生成回答，末句主音收束；尚无多参考融合、对比段或任意续写 |
| 候选与筛选 | 每次尝试生成三个候选；排除复制、整体移调与无效音符，启发式排序；不足时按实际数量显示，无结果明确提示 |
| 素材管理 | 来源 ID、参数、种子、版本、中性音色对照试听、保留候选、不可覆盖的保存快照及重新打开 |
| 导出与交接 | MIDI、MMP、WAV、素材报告；整体工作台将已保留旋律交给步骤一，记录素材池快照及 ID。步骤一仍重新估计调性，尚不继承回答句的和声规划 |

实际使用 Python／Tkinter、Mido、NumPy 和 LMMS，无新服务器、模型或 API。已通过步骤二 18 项自动测试、步骤一原有 19 项回归测试；四份输入共 12 份中性试听实际渲染通过，另完成两次回答句到步骤一的情绪编配渲染。界面导入、候选、保存重开、试听及自动载入步骤一流程通过。

技术通过不等于旋律自然、关联性与新意合格。候选尚待用户对照试听；本轮只标记“首版工程实现完成”，不把完整步骤2听感验收标记为完成。详见[步骤二说明](EmoBlocks-Step2/README.md)和[验收与试听样例](EmoBlocks-Step2/VERIFICATION.md)。

本阶段不包含：完整情绪曲线编辑器、跨块统一编配、自动过渡块、连续整曲导出、任意 WAV 提取、复杂转调、实时游戏播放。它们不是被取消，而是在素材池之后逐步验证。

## 步骤3：结构约束下的情绪适配与连接

> 状态：主题结构约束、有限情绪区间、整段规则编配、边界连接及连续音频的首版工程闭环已实现；音乐听感待验收。独立过渡块、任意时间自由曲线和局部编配保持尚未实现；当前已有块级强度节点拖动。

### 1. 目标

保留用户确认的 A → B → C → D 主题骨架，在允许位置进行原位变体替换与关联素材插入，再逐步实现跨块情绪适配、边界连接及必要的过渡块。不得为了情绪匹配而擅自重排为 A → C → D → B。

### 2. 选择原因（概述）

原段具有前后关系及段落功能，素材池不能等同于任意排列的片段库。先建立结构约束，才能判断情绪调整和连接处理应影响哪些位置；过渡块不能被用来掩盖结构错误。

### 3. 表达方式

在当前工作室切换“精细创作 → 结构”。先确认原主题顺序，再标注段落角色、选用同来源变体和在许可位置插入回答句。例如 A → B_c1 → E（回答 B）→ C → D。

导入顺序仅作待确认建议，角色默认未指定，由用户确认，不宣称程序已理解作品结构。情绪线随后适配此结构，优先改变配器、和声、密度和表达，不擅自打乱原段。

### 4. 实现手段

已实现：

- 固定骨架与独立排列实例；原主题确认后保序、不可省略或重复。
- 变体来源链检查：B 的变体可原位替换 B，E 的变体仍属于关联素材，不能冒充 B。
- 回答句默认在来源原主题之后使用；用户明确确认后可授权其他骨架位置，程序不把授权视为音乐相容性结论。
- 插入、移除插入项、段落角色设置、撤销、结构时长计算及独立快照保存／重开；失败操作不改变原工程。
- 结构工程保留素材副本，不回写步骤一／二素材；新版单窗口工作室会同步后来保留的候选；旧独立结构窗口不保证实时同步。

新增 14 项结构测试、原有 37 项回归测试通过；界面确认骨架、替换、插入、撤销及保存重开流程通过。入口与用法见[整体工作台说明](EmoBlocks/README.md)。

本轮继续实现：

- “情绪与连接”页签支持对连续多个内容块设置统一情绪、起止强度，强度按小节长度分配并显示折线；区间边界暂对齐内容块。
- 全曲统一和声选择、声部与配器规划；六种表达对音色、力度、密度、打击乐及和声偏好起作用。保留骨架及所选主旋律音高／节奏，不通过重排适配情绪。
- 根据边界实际和弦与能量规划末拍低音导向、节奏引入／撤出、首拍伴奏柔化和共同音延留。边界处理不增加小节，报告记录两端内容及动作。
- 共用时间线与音轨一次性渲染，输出连续 WAV、多轨 MIDI、MMP、音符事件、情绪结构快照及处理报告；只有作品末尾保留一秒尾音。
- 支持情绪编辑撤销、快照保存重开及显式连接开关对照。原结构、素材与旧输出不覆盖；当前重新规划整段，不承诺局部修改后其他块伴奏不变。

新增 10 项测试，加上现有共 61 项自动测试通过；基于用户主题生成开启／关闭显式连接的两份作品，各 64 秒主体加 1 秒尾音。逐小节非静音且未检测到削波，界面编辑、撤销、生成及试听流程通过。试听入口与限制见[整体工作台说明](EmoBlocks/README.md)。原主题的单声部整理与演示候选自动选取均记录，不把演示选材视为用户听感认可。

后续：用户试听验收，改进和声与连接自然度；进一步实现局部编配依赖与缓存、有明确时长的独立过渡块、块内情绪类别变化和自由曲线。关闭连接的现有对照仍共享全曲规划，不当作独立块拼接实验。当前不宣称模型能力、任意风格或专业成品质量已完成。

## 当前交互交付：单窗口双模式工作室

> 状态：已实现并验证。此处更新交互承载方式，不改变步骤1～3的音乐能力边界。此前所述独立“素材窗口／结构窗口／情绪窗口”在新版主程序中合并为页签；独立步骤一／二保留，但不会被主程序自动启动。

### 1. 目标

在一个主窗口提供“快速成品”和“精细创作”，并共用素材、当前结构、试听结果与导出能力，避免跨工作窗口操作。

### 2. 选择原因（概述）

快速路径让用户以旋律和情绪线表达目标；精细路径保留已有素材发展、结构约束和连接控制。两者属于同一个项目工作流，快速结果可继续精修，而不是两套彼此隔离的产品。

### 3. 表达方式

- 快速成品：输入一段 4～8 小节旋律，选择 1～6 段情绪发展；自动生成关联回答句、建立结构、分配情绪并输出连续音乐。候选自动选用，不等于用户听感验收。
- 精细创作：素材、结构、情绪与连接三个页签，保留来源检查、原位替换和插入授权；候选保留后同步到结构可用列表。
- 右侧固定显示结果列表、播放／停止、连接说明和 WAV／MIDI／MMP 导出；底部显示进度或错误。
- 支持曲线圆点拖动和区间参数输入；快速生成按钮固定在底部，长页面可滚动。文件选择和导出仍使用系统文件对话框，不启动其他创作程序。

### 4. 实现手段与验收

以单个 Tk 主窗口重新组织界面，后台线程执行生成与渲染；两种模式共用现有规则引擎。新版工程快照统一保存素材、结构、情绪、快速模板、输入设置和结果索引，并兼容旧素材池／结构文件。关闭或新建前自动另存有改动的项目，保存失败不直接丢弃。

新增 9 项自动测试，连同现有共 70 项通过；快速生成、精细修改、结构撤销、实际音频生成、播放、保存重开、导出及主窗口内错误反馈通过。验证中禁止新建工作子窗口，两种模式均可完成流程。

限制仍保留：修改情绪重新规划整段，非局部编配缓存；尚无 WAV 提取、独立过渡块或自由变速转调。快速模式情绪线是新作品模板，精细模式情绪线是当前作品设置，前者不会在未生成时覆盖后者。

入口：[无终端启动](EmoBlocks/launch.vbs)；使用说明见[新版工作室文档](EmoBlocks/README.md)。旧多窗口说明另存为历史记录，不覆盖原始音乐与输出。

### 交互增补：播放定位与多旋律输入

### 问题分析 A：如何锁定主旋律和节奏？

“确定哪部分是主旋律”和“保证生成时不改动它”是两个问题。主旋律可以由用户给定，也可以由系统提取；两种方式最终都需要形成一份已确认的旋律基准，再进行情绪改变。

#### 1）给定：用户明确指定主旋律

- 输入独立的旋律 MIDI，或由用户在多轨工程中指定旋律轨、音符及片段范围。若同一轨内混有伴奏，不默认整轨都是主旋律。
- 将确认后的音符事件保存为不可变基准：音高、块内开始位置、持续时长以及音符数量；休止与音符间隔由这些时间信息共同保留。
- 情绪生成时直接保留该旋律层，只生成或修改允许变化的伴奏、配器与力度，不要求模型重新生成一遍相同旋律。
- 优点：边界清楚，可精确检查，最适合作为步骤1的首个实现范围。限制：用户需要提供或指定旋律。
- 若用户给定的是独立旋律 WAV，可选择原样保留该音频层并添加伴奏，但无法直接编辑其中的音符；若希望换乐器或进行音符级处理，仍需转录，转入“提取”方式。

#### 2）提取：系统识别主旋律，再由用户确认

- 对 MIDI：已有明确音符信息，主要任务是从多个轨道或声部中选择主旋律。轨道名称、音域和音符连续性可作为判断线索，但不能把最高音或最响声部直接当作主旋律。
- 对 WAV：需要识别旋律所在的声部，并估计音高、起音与结束时间；混合音乐可能还需要声部分离。音频分轨不等于主旋律识别，转成 MIDI 也不代表已正确找出主旋律。
- 将提取结果与原音频对照试听，允许用户修正错音、漏音、八度和时值；确认后保存为旋律基准，再使用与“给定”相同的锁定机制。
- 优点：降低用户准备素材的负担。限制：可能误选声部或错误转录，只能保证不改变“确认后的提取结果”，不能据此声称与原始音频中的旋律完全一致。
- 工具参考：[Basic Pitch](https://github.com/spotify/basic-pitch) 可将音频转为 MIDI，并支持弯音；官方说明其在单一乐器输入上效果最好。因此可作为独奏或哼唱输入的转录候选，不应直接视作复杂混音的可靠主旋律提取器。当前仅为候选，尚未在本项目中验证。

#### 两种方式共用的锁定规则

- 默认锁定音高、起音位置和持续时长，不增删主旋律音符；禁止未经允许的移调、八度移动、节奏量化或缩短音符。
- 步骤1固定原速度及速度变化信息，防止拍内位置未变但实际播放节奏被整体加速或减速。后续如允许变速，应作为用户明确开启的另一种约束。
- 默认允许调整音色、力度与伴奏；不能借“演奏方式变化”暗中改变已锁定的起音或时长。若要保留弯音、延音踏板等演奏信息，须将对应控制事件一并纳入锁定。
- 生成完成后逐项对照旋律基准，发现越界则拒绝结果或回退。音符数据不变仍不代表听感完全相同，需试听检查主题是否被伴奏遮盖、音色包络是否明显影响节奏感。

结论：两种方式是同一个功能的不同入口，不是两个产品方向。步骤1优先完成“给定 MIDI 主旋律 → 精确锁定 → 情绪改变”；“提取 → 人工确认”作为后续输入扩展，不扩大当前首个目标。

### 问题分析 B：为什么首版选择这六种表达？

#### 十种候选与取舍

这些名称是面向游戏、影视创作者的配乐表达标签，不是互斥的心理学分类，也不声称穷尽音乐情绪。

| 候选 | 当前选择 | 具体原因 |
|---|---|---|
| 平静／安定 | 首版 | 提供低强度、稳定基线，适合环境铺陈和冲突后平复 |
| 温暖／希望 | 首版 | 覆盖积极但不必高能量的段落，与平静及振奋形成不同表达 |
| 悲伤／失落 | 首版 | 覆盖消极、内收的剧情需要，也能测试高强度悲恸而非只做轻柔版本 |
| 悬疑／不安 | 首版 | 表达未知和未解决；允许低响度、低密度，区别于行动危机 |
| 紧张／危机 | 首版 | 表达危险逼近与行动压力，测试脉冲、加密和持续推进 |
| 振奋／坚定 | 首版 | 覆盖积极高能量与决心表达，使系统不只有平静和负面情绪 |
| 恐惧／惊悚 | 后续 | 常涉及特殊音色、噪声、突发冲击与更强不协和；先避免与悬疑、危机混淆 |
| 愤怒／对抗 | 后续 | 与危机共享部分高强度手法，但敌意、攻击性及风格区分需要额外设计和试听 |
| 神秘／奇幻 | 后续 | 兼具世界观与风格属性，音色和调式语汇跨度较大，首版先缩小范围 |
| 轻快／诙谐 | 后续 | 依赖节奏时机、反差及画面语境；暂不与当前戏剧主线同时展开 |

“悬疑”强调未知，“危机”强调危险迫近；“振奋”强调积极方向，不只是响亮。“高潮”是发展位置和强度目标，可以出现在悲伤、危机或振奋之中，不单独充当第七种情绪。

#### 为什么不使用固定乐器配方？

情绪表达由音区、调式、速度、力度、发音方式、音色等共同参与，具体效果取决于音乐语境。实验研究考察了这些线索的贡献与组合，不能据此把单个参数当作普遍的情绪开关。[音乐情绪线索实验](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2013.00487/full)

影视配乐还涉及剧情意图与音乐在场景中的功能；同一个情绪标签不一定对应同一种处理。[伯克利影视配乐课程说明](https://www.berklee.edu/online-registration-manual/course-descriptions/film-scoring)

以上六种的具体候选手法是本项目的初始设计假设，需要通过多旋律试听检验，不是已经验证的自动情绪公式。

### 问题分析 C：手法判断采用规则还是 AI？

#### 当前结论

二者不是互斥选择。确定性规则负责可执行边界、初始方案和检查；模型可以负责更丰富的候选或上下文规划。第一版先完成规则驱动的自动闭环，不要求用户替系统作编配决策，也不把规则系统称为训练出来的情绪模型。

上下文判断至少考虑：参考旋律及其乐句、当前目标情绪和强度、前后块情绪、可获得的和声／配器信息、用户允许的变化程度。没有前后块时采用独立段落计划；只知道前后标签时，不虚构实际和声与音色信息。

#### 同一“平静”在不同上下文中的设计示例

| 上下文 | 可采用的自动策略 |
|---|---|
| 悲伤 → 平静 → 温暖 | 保留部分前段音色，逐步解决和声，再引入柔和回应 |
| 危机 → 平静 → 结束 | 撤掉脉冲与鼓组，保留适量尾音，使乐句获得落点 |
| 平静 → 平静 → 危机 | 主体保持稀疏，后半段逐渐引入低音脉冲或悬置 |

这些是可编码策略示例，尚不构成听感保证。未来引入 AI 时，也应在受限方案空间内提出计划，而不是任意更换所有音乐内容。

#### 可复用工具及边界

| 项目 | 对应作用 | 采用边界 |
|---|---|---|
| [music21](https://music21.org/music21docs/testsAndInProgress/devTest_unconvertedExamples.html)／[musicpy](https://github.com/Rainbow-Dreamer/musicpy) | 音符变换、和弦与音乐结构操作 | 是程序工具，不负责自动判断何时使用某种情绪手法 |
| [MMA](https://www.mellowood.ca/mma/) | 可由程序调用的自动 MIDI 伴奏 | 系统仍需提供和弦及编配指令，不是任意旋律的情绪理解器 |
| [AccoMontage2](https://github.com/billyblu2000/AccoMontage2) | 旋律到和弦／伴奏，控制节奏密度与声部数量 | 研究项目；接口含调性、4/4 拍及 4／8 小节分段要求，需验证资源和环境 |
| LMMS | 音色播放、音频渲染与工程交付 | 本机已完成演示；不代表所有音色、插件及任意工程均受支持 |
| [GETMusic](https://github.com/microsoft/muzic/tree/main/getmusic) | 基于已有音轨生成其他音轨、指定区域补全 | 后续候选；不自带本项目的六情绪决策规则 |
| [Music SketchNet](https://github.com/RetroCirce/Music-SketchNet) | 单声部音高／节奏控制与局部补全 | 后续候选；不能直接等同于多轨情绪重编系统 |

候选项目尚未在本项目内完成集成验证；代码、模型权重和素材的使用条件需分别确认。自动化的核心责任仍由 EmoBlocks 承担：把用户目标转换为编配计划，执行、筛选、回退，并交付结果。

### 问题分析 E：阶段完成后，为什么建议先做块间连接与局部修改？

当前原型已经能改变一个块的编配，但还没有把它变成可反复组合和修改的音乐积木。下一阶段最直接的验证是：块与块之间能否自动连接，以及修改中间一块时能否保留已确认内容。

- 不优先增加更多情绪：六种表达已经覆盖初期戏剧需求，应先通过试听确认有效性；增加标签不能替代组合能力。
- 不优先制作完整情绪曲线：在尚未验证块间变化与边界修复前，连续曲线可能只成为参数界面，无法保证音乐连续表达。先建立有限块的可解释关系。
- 不将大模型接入作为前置条件：规则连接可以先验证工程与交互价值，模型后续作为变奏或过渡候选来源；如果单块听感明显不足，先修正规则或替换对应生成模块。
- 先用同一参考主题与统一速度、调性上下文：减少无关差异，便于判断问题出在过渡、配器还是素材本身。该限制是首轮验证范围，不代表未来产品只支持一种主题。
- 不能只读取情绪标签：两个都标记为“平静”的块也可能有不同和弦与音区，因此连接需要实际音符和和声信息。
- 不能只拼接独立音频：单块导出的尾音、末尾淡出及独立空间效果可能破坏连接处的连续性，需要在共同时间线上安排并渲染。
- 局部修改与主题变奏并不冲突：目标块仍可进行允许的变奏；“保留其他块”指保留用户已确认内容，不是恢复为所有块逐音符严格锁定。
- 缓存与验证分层：先确认未受影响的音符和声部事件不变；若共用效果尾音或主总线影响相邻采样，应报告实际影响区，不夸大为混音文件逐采样完全不变。

以上为步骤2的待确认建议，不代表已启动开发，也不覆盖步骤1尚待完成的听感评估。

### 问题分析 F：为什么把当前步骤2调整为素材池与内容发展？

#### 创作顺序与开发顺序

最新 Idea 的创作顺序是先从 A/B/C/D 发展素材（含关联新素材 E/F/G），再设计情绪线。步骤1先做单块情绪引擎属于技术验证顺序，可以保留复用，不必推翻；但步骤2应补上内容层，不能继续只围绕同一旋律的不同情绪版本设计所有数据与交互。

Idea 文档中的 MVP 条目属于此前的阶段划分。本计划此次把“一种受限关联新素材生成”提前到当前步骤2验证，不表示把完整 E/F/G 创作模型、情绪线和连接一并提前。本轮后续实施以本计划为准。

#### 三个需要分开的概念

- 内容变化回答“奏什么”：A 与 A_c1 的关系、A/B 如何发展出 E。
- 情绪演绎回答“怎样表达”：同一 A 在不同情绪下的配器、力度、密度及允许的变化。
- 连接回答“怎样从此处到彼处”：边界交接或有明确两端和时长的过渡块。

这三个层次共用来源和版本管理，但不是三个产品方向，而是同一个“少量主题到可控情绪作品”流程中的依赖环节。E 是可独立复用的内容，过渡块则依赖指定的起点和终点。

#### 为什么不只做素材管理，也不一次做完 E/F/G？

只做导入和命名会得到一个素材文件夹，无法验证内容发展价值；直接要求任何主题都能生成优秀新旋律，又会使步骤2变成开放式自动作曲。折中方案是“素材管理＋有限变体＋一种回答句生成”，让工程闭环与音乐风险同时可见。

难度估计：素材管理、保存和试听为低到中；内容变体为中；既相容又有新意的回答句为中高，且听感不确定性最高。首先用现有本地工具与规则验证，不因效果不足就直接假定购买算力能解决问题；需要时再独立评估模型与音源。

#### 之后如何接回情绪线和连接？

素材准备完毕后再设置情绪区间，区间与素材边界保持独立。统一规划跨块配器、和声与能量，再处理边界，不能把独立块简单渲染后拼接当作跨块情绪规划。

原步骤2提出的局部影响范围、内容不变检查、尾音管理和可撤销连接仍有价值，移入后续阶段。历史方案中的“两侧各一小节、不额外增加小节”只描述当时的边界处理原型；将来若实现独立过渡块，需要明确计入其时长，而不能继续套用该限制。

### 历史记录 G：被替代的步骤2建议

早期建议直接连接同一主题的不同情绪版本，后调整为先建素材池、再做结构与连接。局部影响范围、尾音管理和未修改内容保持仍是后续要求。[完整原文存档](EmoBlocks-decision-history.md)。
