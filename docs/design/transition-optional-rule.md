# 连接处理统一规则

**无需过渡也是有效结果。** 此规则统一适用于完整 Bridge 乐句、连接块和最后的块间边界处理，不因情绪不同、四拍分界或存在可写时间就强制添加过渡。

补全与推荐先解决待补全区域；随后判断 Bridge 的位置并锁定保护，再判断连接块，最后处理块间边界。每一层独立判断是否有必要，不需要某一层不影响后续层正常运行。

| 情况 | 处理与验收 |
| --- | --- |
| 现有旋律已自然成立，无额外音乐收益 | 合法 `none`；保留原音符和时长，后续正常编配、渲染、试听、确认与导出 |
| 需要处理，但完整保护、主动留白或时间约束不允许 | 如实说明无合法窗口或操作；保留主体，不延长作品，不覆盖保护 |
| 已有合法且有收益的窗口 | 生成并独立检查实际音乐；不能通过总是返回 `none` 规避正例验收 |
| 用户明确关闭某层处理 | 保留原音乐并记录关闭策略，不宣称自动判断了所有窗口 |
| 搜索不完整、预算耗尽 | 保留现有结构化失败或未完成说明，不改写为已经证明“无需过渡” |
| 取消、异常、过期输入或输出未通过认证 | 不视为合法无过渡，不覆盖当前编辑与已有有效结果 |

结果中的已有字段、原因码、算法版本和哈希语义保持不变。Bridge 的 `NO_PREDICTED_GAIN`、`NO_WRITABLE_WINDOW`，连接块的 `NOT_NEEDED`、`NO_LEGAL_WINDOW`，边界的 `NOT_NEEDED`、`NO_LEGAL_OPERATION` 各保留准确含义；`SEARCH_INCOMPLETE` 不等同于已经证明 `NOT_NEEDED`。

验收同时包含自然无过渡、确实需要过渡、保护禁止改写、预算不足和取消等案例。真实 Bridge 正例检查生成音符经过后续连接后仍受保护；真实无 Bridge 案例不能因缺少 Bridge 被判失败。自动测试与渲染成功不代表人工音乐听感已经通过。
